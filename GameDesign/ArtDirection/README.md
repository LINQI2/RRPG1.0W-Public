# RRPG Art Direction｜美术方向专题入口

> 版本：V0.1  
> 状态：**Concept / Not Fully Frozen**  
> 用途：把 RRPG 当前美术探索从聊天里的“感觉”沉淀为可复盘、可比较、可继续收敛的设计资产。  
> 注意：本专题不是 GameSpec，不冻结具体摄像机参数、头身比、Palette、线宽、Rig、UI Layout 或正式资产规格；任何开发落地仍需独立规格与授权。

---

## 1. 为什么需要这个专题

RRPG 的美术方向不能只用“干净、2.5D、卡通、明亮、立体”这类抽象词描述。相同词汇在不同游戏、美术师和 AI 眼里可能指向完全不同的画面。

因此，本专题采用一个强制原则：

> **抽象词必须绑定视觉参照和对照。**

例如，不单独写“喜欢大团块”，而要说明：

- 正向参照：《Dorfromantik》里森林、农田、水系、聚落先被读成区域块；《咩咩启示录》村庄也比《饥荒》更偏大区域组织。
- 反向参照：《饥荒》大量小单位以散点方式构成荒野，整体更自由、碎、野。
- RRPG 当前含义：允许小物件丰富，但第一眼应先读到“森林块 / 农田块 / 居住块 / 公共空间”，而不是几十个同权小物件。

以后新增任何美术结论，都优先回答四件事：

1. **我说的抽象词到底指什么视觉现象？**
2. **哪几款游戏最接近？**
3. **哪几款游戏是反例或边界？**
4. **RRPG真正要继承的是哪一层，而不是整包抄哪款游戏？**

## 3. 参考的使用规则

### 3.1 不允许整包引用一款游戏

禁止：

> RRPG 美术 = 《恶果之地》风格。

正确：

> 《恶果之地》当前主要承担综合色彩、图形清洁度、非人物造型、怪物可读性、UI简洁度等参考；人物手臂比例并不采用。

### 3.2 参考分两类

**直接结构参考**：与 RRPG 的观看方式、产品结构比较接近，可看整体。

例如：

- 《Norland》：多人物共同体、斜俯视村庄、建筑与家具空间关系。
- 《漂泊牧歌》：模拟经营、生活世界、2D/2.5D动画尺度。
- 《咩咩启示录》：小人共同体、村庄团块、2D人物与地面关系。

**单项技术参考**：产品结构可以完全不同，只学习一个问题。

例如：

- 《Spiritfarer》：干净木材、稳定动画线；不拿它的侧视结构作为 RRPG 村庄空间答案。
- 《Hades》：建筑硬表面体块、明暗转折、战斗 Pose；不整包继承综合色调和战斗特效密度。
- 《模拟人生》：人物动作表演与性格步态；不是视觉视角参考。

### 3.3 抽象术语需要至少一个“像什么”和一个“不像什么”

例如：

- “干净”不是“没有细节”。
- “立体”不是“必须3D”。
- “卡通”不是“统一大头”。
- “高可读性”不是“必须黑描边”。
- “丰富”不是“全屏高频细节”。

若无法找到具体视觉参照，则该结论继续保持 Pending，不升级为正式方向。

## 4. 当前最高层的总纲

目前反复出现、跨多个维度相互验证的核心原则是：

> # **视觉层级优先于视觉简化。**

RRPG 并不追求“越简单越好”。

它可以有丰富建筑、家具、植物、事件插图和人物差异，但必须满足：

> 第一眼先读大结构；  
> 第二眼读中尺度设计；  
> 第三眼才发现小细节。

同一原则已经分别出现在：

- Village 的大团块空间；
- 《Dorfromantik》式小物件组块；
- 地面的低频视觉休息区；
- 材质的结构细节优先；
- 《恶果之地》的背景纹理密度与角色大色块分离；
- UI 的信息组块；
- 多人物动画的疏密；
- AI生产中的“复用结构、生成内容”。

这条原则目前比“要不要粗描边”“到底几头身”更接近 RRPG 的真正美术 DNA。

## 5. 下一阶段如何继续

顶层视觉坐标完成 V0.1 后，下一层再按对象建立视觉母语：

- Person / 人物母语；
- Building & Environment / 建筑环境母语；
- Monster / 怪物母语；
- UI / UI母语；
- Event Illustration / 事件插图母语；
- Motion / 动画母语；
- VFX / 特效母语。

这些子专题必须继承顶层原则，但允许拥有各自更具体的规则。

**不要从顶层直接跳到资产清单。**

正确顺序仍然是：

> 顶层视觉架构  
> → 对象母语  
> → Visual Bible / 可执行规范  
> → 视觉实验  
> → 正式资产生产。
