# RRPG 顶层美术架构 V0.1

> 状态：**Concept / Not Fully Frozen**  
> 性质：Current Art Direction Working Model / 当前美术方向工作模型  
> 目的：沉淀当前已经通过多轮游戏对照形成的视觉偏好、原则、参考职责与未决边界。  
> 非目标：本文件不冻结精确摄像机参数、头身比、正式 Palette、具体线宽、最终 UI Layout、Rig 结构、正式资产数量或 Unity 实现方式。

---

# 0. 当前总方向

RRPG 当前逐渐形成的美术目标不是“极简”，也不是“高细节”，而是：

> **清晰、可读、长期耐看、有体积、有生活感、有足够丰富度，但所有丰富度必须被组织。**

目前最强的跨维度原则：

> # 视觉层级优先于视觉简化。

允许细节丰富；不允许所有细节同权。  
允许颜色鲜艳；不允许综合色彩糊成一片。  
允许 UI 信息量增加；不允许散乱。  
允许大量人物活动；不允许所有人物持续抢焦点。  
允许 AI 大量生成内容；不允许每个资产重新发明一套结构。

RRPG 想形成的不是“某一款现有游戏的复制品”，而是不同层级的参考经过统一视觉语法后形成的新体系。

# 1. 维度与空间形式

## 1.1 当前方向

**2.5D / 斜俯视 / 伪立体** 是当前强方向。

这里的 2.5D 不是简单的“2D图片放进3D摄像机”，而是：

- 2D或2D化资产拥有稳定的前后关系；
- 建筑与人物存在遮挡与接地；
- 地面、建筑、人物、植物拥有统一空间关系；
- 通过体块、光影、投影、AO、地形结合减弱纸片感；
- 不追求重3D生产成本，但希望获得明显高于纯平面2D的空间可信度。

## 1.2 视觉参照

**正向：**

- 《Norland》：斜俯视共同体世界、多人长期生活、建筑与家具真正存在于空间里。
- 《咩咩启示录》：2D小人与斜俯视地面结合；尽管真实光照很弱，但通过结构、接地装饰和地面绑定减弱贴图感。
- 《Hades》：硬表面、立方体建筑的明暗面转折非常强，可作为体积塑造技术参照。

**技术参照：**

- 《八方旅人》：证明“2D角色 + 3D/立体空间 + 光照”也是2.5D的一条路线，但不代表RRPG要采用HD-2D具体画法。

**边界 / 反例：**

- 纯平面卡牌类画面只能说明2D是什么，不适合作为Village空间目标。
- 《纸片马里奥》故意强调纸片属性，RRPG不希望把“纸”本身作为世界材质逻辑。

## 1.3 Pending

- 精确摄像机倾角、透视强度、FOV；
- 角色与建筑最终采用纯Sprite、2D Rig、2D/3D混合中的哪种实现；
- 正式接地阴影、Normal、2D Light等技术方案。

# 2. 空间颗粒度与视觉组块

## 2.1 当前强方向

RRPG Village 更偏：

> **中大空间颗粒度 + 大团块先读 + 小物件组块化。**

“干净”不等于“小物件少”。

关键在于玩家第一眼读到什么单位。

例如几十棵树如果被组织为一个明确森林区，第一眼读到的是“森林块”，而不是几十个同权树Sprite。

## 2.2 核心参照

**《Dorfromantik》**：

- 单棵树、单栋房都很小；
- 但几十棵树融合成森林；
- 多栋房融合成聚落；
- 农田、水系、草地形成大区域；
- 地面留有大量安静区域，因此即使小物件很多也不乱。

**《咩咩启示录》村庄**：

- 相较《饥荒》，玩家更容易先读到建筑区、祭坛区、道路、功能区等大结构；
- 适合作为“共同体空间为什么比荒野更有组织”的参考。

**《饥荒》作为对照：**

- 空间更多由树、草、石头、机器等大量独立小单位构成；
- 更散、更野、更自由、更像荒野生存；
- 这种视觉语法不适合直接成为RRPG长期村庄的骨架。

## 2.3 RRPG含义

Village 应先形成：

- 居住块；
- 农田块；
- 森林/自然块；
- 公共空间；
- 生产/工作区；
- 道路、水系或边界。

然后再在这些块内部增加家具、招牌、工具、植物、小道具。

> **小碎件作为丰富度，不作为空间骨架。**

# 3. 人物比例、人口感与身份连续性

## 3.1 当前方向

普通人物倾向：

> **中度卡通化 + 相对自然的人体结构。**

不是写实人体，也不倾向极端Q版、统一大头、大肚子玩具型或高度符号化人体。

RRPG 的核心不是“20个主角站在一起”，而是“一群具体的人共同生活”。

因此人物体系必须支持：

- 儿童；
- 成人；
- 老人；
- 高矮；
- 胖瘦；
- 不同性格/姿态；
- 长期身份成长。

## 3.2 参考与边界

**《Hades》《守望先锋》**：

- 人体结构完整；
- 游戏化造型明确；
- 身体不是简单玩具块；
- 作为“自然人体基础仍可有强设计”的技术参照。

**《恶果之地》**：

- 当前并不作为人物比例主要目标；
- 用户喜欢它的综合色彩、非人物、图形语言更多；
- 人物手臂过长是明确不喜欢点。

**《咩咩启示录》**：

- 多教徒共同体的群体统一感值得参考；
- 但统一幼态、大头比例不应直接推导为RRPG人物母版。

**《动物森友会》**：

- 群体一致性很强；
- 但整体过于圆润、可爱、玩具化，不适合直接成为普通RRPG村民。

**《饥荒》《脑航员2》**：

- 角色造型过于独特、怪、主角化；
- 更像独特可操作角色，而不是长期共同体里的普通人口。

**《胡闹厨房》**：

- “大头 + 大肚子 + 短四肢”的玩具型Q版明确不喜欢。

## 3.3 年龄方向

当前工作模型：

- 儿童天然头身比更大、步幅更小；
- 成人作为基础人体阶段；
- 老人保持基本人体连续性，更多通过姿态、步态、发型、服装、状态表现年龄；
- 不做“成年突然换人体模板”“职业导致身体重塑”。

## 3.4 身份连续性

> **身体是人的长期底座；身份通过服装、装备、姿态、动作和局部轮廓增强。**

一个矮壮的人成为猎人后，仍是矮壮的猎人；高瘦的人则成为高瘦的猎人。

Hero 可以提高造型显著度，但不应变成另一种人体比例体系。

# 4. 造型语言 Shape Language

## 4.1 当前方向

整体倾向：

- 规则；
- 结构明确；
- 大体块稳定；
- 圆与方结合；
- 少量尖锐形承担危险、异物、敌意；
- 不追求普遍歪扭、毛躁、随机不规则。

## 4.2 “规则”不等于“死板”

RRPG 并不是要求所有房子方方正正、左右对称。

更准确的含义：

> 大体块、结构转折、轮廓层级具有设计秩序；局部允许不对称和自然变化。

## 4.3 参考

**《恶果之地》**：

- 非人物造型、装饰、植物、怪物、图形语言是当前最强参考之一；
- 植物可以“繁而不杂”；
- 怪物往往简洁、轮廓明显；
- 单体有设计感，但整体仍保持大色块和清晰结构。

**《Hades》建筑**：

- 中大型体块清楚；
- 点线面关系比大量随机细线更成熟；
- 方整硬表面尤其有强体积与结构感。

**《咩咩启示录》建筑作为边界：**

- 宏观团块和干净地板值得参考；
- 但局部建筑、草丛等存在大量同权线条，粗细和层级不足；
- 因此“整体清楚”不代表“局部造型质量就是目标”。

# 5. 色彩、明度与可读性

## 5.1 当前强方向

用户对色相本身并不特别敏感，但对：

- 大色块；
- 明度结构；
- 主体/背景分离；
- 低视觉噪声；
- 清晰焦点；

非常敏感。

因此RRPG不应被概括成“高饱和风”。更准确是：

> **中高明度为主、适度鲜艳、大色块优先、限制综合色彩层级、低视觉噪声。**

## 5.2 核心参照

**《恶果之地》大多数清晰场景：**

- 大底色稳定；
- 角色和怪物更鲜艳、更完整；
- 地面不持续抢注意力；
- UI简洁；
- 视觉焦点明确。

**《恶果之地》部分紫色场景作为内部反例：**

- 蓝紫、灰紫、暗红紫、中暗值大量接近；
- 环境染色强；
- 主体与环境粘连；
- 用户会产生“黏糊、暗、糊”的感受。

这说明喜欢《恶果之地》不等于接受它所有配色场景。

**《Hades》：**

- 色彩不是主要偏好来源；
- 整体常偏暗，叠加环境特效后人物可能糊；
- 建筑塑形值得学，但综合色彩与视觉噪声不直接继承。

**《Hi-Fi Rush》作为边界：**

- 单独看鲜艳明亮、三渲二很漂亮；
- 但整屏高频视觉信息过多，整体太花；
- 说明“明亮鲜艳”不能代替层级。

## 5.3 色觉可访问性

用户存在红绿色弱，并较难区分部分紫/蓝、灰绿/灰红。

因此重要信息不得只依赖色相差：

- 友军/敌军不能只靠红绿；
- 状态不能只靠相近灰色系；
- 关键角色/目标需要同时利用形状、轮廓、图标、位置、明度、动画等冗余编码。

未来视觉验收建议固定加入：

- 灰度检查；
- 缩略图检查；
- 色觉模拟检查。

# 6. 细节密度、疏密与视觉层级

## 6.1 当前核心结论

> **干净 ≠ 没有细节。**

用户并不喜欢《TUNIC》《Death's Door》那种过于简略、长期缺少观看丰富度的世界。

RRPG Village 是长期的“家”，玩家会反复观看，因此需要足够丰富的中尺度设计。

但反感：

- 极小碎线；
- 点状噪声；
- 地面均匀铺满纹理；
- 整屏所有区域同样复杂。

当前方向：

> **大形强 + 中形丰富 + 小形克制。**

## 6.2 参考

**《Dorfromantik》**：

- 小物件很多；
- 但密的地方形成完整团块；
- 空的地方真的空；
- 地面提供呼吸区。

**《Hades》建筑局部：**

- 单独建筑的大、中细节分配合理；
- 真正造成“乱”的常常是地板碎块、血迹、战斗特效、环境氛围叠加，而不是所有建筑本身。

**《Hi-Fi Rush》：**

- 局部很漂亮；
- 全屏同时高密度，超过用户长期舒适区。

# 7. 材质语言 Material Language

## 7.1 总方向

> **Clean Stylized Material / 干净的风格化材质。**

材质主要靠：

- 大色面；
- 结构；
- 光影；
- 少量有意义的中型细节；

而不是依赖：

- 满屏木纹；
- 大量小斑点；
- 模糊笔刷；
- 均匀脏污。

核心原则：

> **Structural Detail > Surface Noise**  
> 结构细节优先于表面噪声。

## 7.2 分材质当前参照

### 木头

**《Spiritfarer》最舒服：**

- 大面干净；
- 少量结构线就能读出木材；
- 不需要表面铺满木纹。

RRPG 可以借它的材质压缩方式，同时用更强空间光和体块解决“太平”。

### 石头

**《Hades》《恶果之地》更合适：**

- 边缘细、硬、清楚；
- 内部使用直裂纹、掉角、中型破损面；
- 不靠模糊毛躁笔刷堆石质。

《Bastion》部分石材因边缘毛躁、软、模糊而不符合当前偏好。

### 家具

**《Norland》的桌椅、木桶、部分墙体：**

- 结构本身就是细节；
- 大色块清楚；
- 体积好。

而某些路灯等复杂物件内部细线太多，缩小后糊成一团，是明确边界。

### 地面

地面承担**视觉休息区**。

喜欢：

- 《恶果之地》干净草地；
- 《Norland》部分低频草地；
- 《漂泊牧歌》草地；
- 《Hades》部分低纹理石板、红毯。

不喜欢：

- 《Bastion》非常碎的地面；
- 《Norland》部分碎地板；
- 《Hades》某些均匀铺满高频纹理的地砖。

### 屋顶

《Norland》是当前主要结构参照，但瓦片等重复细节还希望进一步概括。

### 布料

当前 Pending。

倾向假设：大褶皱、大明暗面、少量边缘和结构线，不追求纤维噪声。

### 金属

当前 Pending。

多数手绘金属通过碎灰蓝色块和脏污模拟金属，不喜欢。当前更倾向未来寻找：

- 更硬边；
- 更高明暗跨度；
- 更窄、更亮的高光；
- 少量明确反射带；

的干净卡通金属。

# 8. 光照语言 Lighting Language

## 8.1 当前方向

RRPG希望拥有：

> **统一世界光感 + 清楚体积 + 可长期阅读 + 局部视觉焦点。**

并不满足于“每张Sprite自己画一点假高光”。

## 8.2 核心参照

**《Norland》：**

- 当前整体光感最舒服；
- 更像整个世界共享一个光照环境；
- 建筑、屋顶、地面、家具能产生相互统一的空间关系。

**《咩咩启示录》作为边界：**

- 投影非常浅；
- 很多灯不真正影响周围；
- 立体感更多靠建筑结构、地面绑定、土包/底座等“接地设计”补足；
- 说明接地可补光弱，但不是RRPG当前主目标。

**《Hades》：**

- 方整、立方体硬表面的大面转折非常有体积；
- 柱子、圆体的立体感相对弱；
- 因此参考重点是“硬平面之间的大明暗差”，不是整套光照照搬。

**《冰汽时代》：**

- 夜间冷环境 + 暖灯火形成强家的感觉和视觉焦点；
- 可作为“夜晚不只是整体变暗”的重要参照。

**《奥日》系列：**

- 重点目标通过局部光、边缘光保持可读性；
- 只作为局部强调光技术参照。

## 8.3 昼夜工作模型

白天：

- 整体清楚；
- 有统一方向光；
- 可允许大片阴影，但不能让重要操作区不可读；
- 局部借《Hades》硬表面体积塑造。

黄昏：

- 可提高戏剧性；
- 冷暖关系变强；
- 适合“共同体回家/工作切换”的氛围。

夜晚：

> 不是“白天画面 × 0.6亮度”。

而是：

- 环境整体压暗；
- 火、窗、路灯、特殊建筑形成暖光视觉节点；
- 村庄仍然“活着”。

## 8.4 2D/2.5D实现原则（非技术冻结）

未来资产不应把所有时段强光都完全烘死在一张源图里。

可考虑的技术手段包括：

- 全局环境色；
- 独立光照层；
- Emission Mask；
- Shadow Sprite；
- Normal/2D Light；
- 不同时间状态贴图；

具体选择交给后续技术验证。

# 9. 线条、边缘与主客体分离

## 9.1 上位原则

经过对比后，真正偏好并不是“必须黑描边”，而是：

> **Figure–Ground Separation / 主体与背景必须清楚分离。**

描边只是实现清晰度的一种手段。

还可以依赖：

- 明度；
- 饱和度；
- 大色块；
- 疏密；
- 空白；
- 光照；
- 轮廓；
- 动态。

## 9.2 《恶果之地》的启发

背景树林可以有大量密集线和纹理，但当它们聚成一块后，反而退为纹理背景。

战场地面较干净；人物与怪物是完整、鲜艳的大色块，因此主体跳出。

因此：

> **密不一定是焦点；稀不一定是焦点。焦点来自相邻区域之间的对比关系。**

## 9.3 建筑线面关系

当前倾向：

> **面承担结构，线承担信息。**

建筑体积主要由：

- 顶面；
- 正面；
- 侧面；
- 屋檐暗面；
- 凹槽；
- 接地阴影；

构成。

线条更适合承担：

- 梁柱；
- 瓦片边界；
- 窗框；
- 裂纹；
- 装饰。

## 9.4 参考

**《Spiritfarer》**：干净稳定的动画线、内部线克制。  
**《恶果之地》**：清晰轮廓 + 大色块 + 背景/主体强分离。  
**《Hades》**：大量区域不依赖粗黑描边，而靠色面/明暗转折。  
**《饥荒》反例**：大量物体都拥有强手绘线、同权高频边缘，容易整体竞争。  
**《Hi-Fi Rush》技术参考**：单独角色的强轮廓 + 大色块很好，但整屏密度不作为目标。

---

# 10. UI与世界的关系

## 10.1 当前方向

RRPG不是“世界画面优先、UI尽量消失”的壁纸型产品。

更准确是：

> **World-first，但不是 World-only。**

Village世界负责让玩家看见共同体；UI负责理解、组织、管理共同体。

## 10.2 信息哲学

当前倾向：

- 顶部状态/时间/基础资源信息合理常驻；
- 底部或其它稳定导航承担主要功能入口；
- 侧边/上下文面板按需出现；
- 信息可以随游戏深度逐步增加；
- 玩家可以收起，但不能为了“干净”而缺失必要管理信息。

## 10.3 组块化

和Village空间同样，UI也偏好：

> **Chunking / 信息组块。**

不是15个小图标散落屏幕，而是让玩家先读成：

- 资源区；
- 时间区；
- 人物管理区；
- 行动区；
- 上下文区。

## 10.4 参考

**《冰汽时代》**：

- UI自身具有很强世界观画风；
- 信息不是纯软件工具样式；
- 当前是“UI应该有风格”的重要参照。

**《漂泊牧歌》**：

- 在当前看过的模拟经营 UI 中较接近产品结构需求；
- 但并不是最终答案。

**《Norland》边界：**

- 产品结构很值得参考；
- UI较散、导航层级不够漂亮，不作为视觉目标。

**《Dorfromantik》《Bad North》**：

- 可学习留白和清晰；
- 但玩法简单、管理信息少，不能反推RRPG也应该把UI极度削减。

# 11. 事件插图与叙事视觉

## 11.1 事件是重要视觉玩法

事件不是简单文字弹窗。

RRPG拥有较多事件和选择，它们本身可以提供：

- 随机性；
- 开盲盒感；
- 抉择感；
- 视觉奖励；
- 世界和共同体叙事。

## 11.2 当前最强插图方向

> **Dramatized Concrete Narrative Illustration / 戏剧化的具体叙事插图。**

要求：

- 即使不读文字，大致也能联想到发生了什么；
- 不是机械白描事件；
- 从事件里选择最有戏剧张力的瞬间、人物、动作或构图；
- 可以强化风雪、光线、姿态、留白、群像等情绪；
- 但不能抽象到只画一个象征物就失去事件本身。

## 11.3 参考

**《冰汽时代》优质事件插图：当前最强参考。**

例如：

- 风雪中的人；
- 空碗；
- 群众人影；
- 法律抉择中具有戏剧性冲突的图像。

优点在于：

> 仍然在画“事件”，但比普通说明图更戏剧化、更有情绪。

**《Six Ages / 六纪元》：稳定下限参考。**

- 大量事件坚持把事情完整画出来；
- 每张未必极具戏剧性，但稳定具有观看价值；
- 排版本身不是目标。

**《王国棋境》（按当前讨论名称）作为波动参考：**

- 某些冲突/人物事件图很好；
- 某些只画单一象征物（例如一个心脏式符号）观看价值低；
- 因此不再把“王国棋境事件画风”整体视为目标。

**《漫野奇谭》（Wildermyth）**：

- 具体Person、关系、漫画式事件演绎很有启发；
- 但RRPG不必把所有随机人物事件都重新生成漫画插图。

## 11.4 多种事件表现模式并存

未来不需要强制全部 Event 使用一张图。

可以并存：

1. **戏剧化叙事插图模式**：重大事件、社会事件、世界事件；
2. **具体人物演绎模式**：调用真实 Person 视觉资产 / Spine / 立绘进行对话与动作；
3. **Village 世界内演绎模式**：镜头移动到真实人物所在位置，在世界中发生；
4. 重要事件甚至可以组合以上模式。

固定剧情可以制作固定人物插图；随机Person事件优先复用真实Person资产，避免把“AI每次准确重画同一个随机人物”变成所有事件的硬依赖。

## 11.5 构图景别不冻结

不同事件可使用：

- 近景人物情绪；
- 中景多人关系；
- 大全景灾害/村庄/战争；
- 物件特写；
- 适度象征构图。

由事件内容决定，不强制所有卡面同一景别。

# 12. 动效 / 动画语言 Motion Language

## 12.1 核心方向

> **Natural Base + Stylized Acting**  
> **自然基础动作 + 风格化人物表演。**

普通人首先像人在生活，而不是吉祥物一直弹跳，也不是贴图平移。

性格、职业、情绪、事件发生时再提高表演性。

Battle 再提高一级动作强度。

## 12.2 直接参考

**《漂泊牧歌》：当前2D/模拟经营动画尺度最喜欢的参考。**

- 不像符号单位那么死；
- 不像《缺氧》那样全程高度卡通；
- 在生活世界和风格化动画之间提供有价值的中间尺度。

**《模拟人生》：核心动作导演参考。**

- 基础走路像正常人；
- 不同性格可以拥有不同步态和动作气质；
- 普通状态自然，情绪出现时会明显夸张；
- 非常适合RRPG“具体Person”的表演逻辑。

**《Hades》：只负责Battle动作参照。**

- 强Pose；
- 发力节奏；
- 攻击反馈；
- 不作为Village日常动作比例和强度的目标。

## 12.3 边界

**《RimWorld》《Clanfolk》《Norland》**：

- 更偏符号移动；
- 大量行为靠贴图移动、工具图标/简单动效表达；
- 对RRPG人物生命周期和具体Person表演而言不足。

**《缺氧》**：

- Action Readability 很强；
- 但整体卡通夸张程度过高，不符合生老病死共同体的长期人体气质。

**《咩咩启示录》**：

- 大量居民动作活泼；
- 但全员幼态、统一年龄气质，无法直接承担RRPG人口生命周期。

## 12.4 人口动画层级

- 普通Idle：轻；
- 行走：自然、清楚；
- 工作：语义明确；
- 对话/情绪：适度夸张；
- 身份/职业：通过Pose、工具、习惯动作增强；
- Hero：允许更强动作辨识；
- Battle：强Pose、强节奏、强反馈。

多人同时出现时必须控制动画疏密，不能让20个人持续同时抢焦点。

## 12.5 年龄与性格

人物动画应允许：

- 儿童步幅/重心不同；
- 成人作为基准；
- 老人根据健康和个体状态产生不同步态，而不是统一“驼背慢走”；
- 性格可以通过少量运动气质层（稳重、轻快、谨慎、疲惫、自信等）覆盖基础动作。

具体动画系统和Spine实现仍未冻结。

# 13. 生产语言 / AI时代美术架构

## 13.1 总原则

> **AI负责高变化，人类规则负责高一致。**

以及：

> # **Reuse Structure, Generate Content.**  
> **复用结构，大量生成内容。**

传统独立游戏常因“画图太贵”压缩资产量；RRPG 在生成式AI条件下，新的主要瓶颈逐渐变成：

- 风格一致；
- 结构一致；
- 资产筛选；
- 可修改性；
- 可动画性；
- 导入与配置；
- 长期维护；
- 来源追溯。

生成速度不是唯一目标。

## 13.2 资产分类

### 高变化、低结构约束：AI重度参与

适合：

- 事件插图；
- 特殊世界事件画面；
- 部分怪物概念；
- 特殊遗迹；
- 情绪图；
- 营销图；
- 某些环境装饰变体。

### 高一致、高复用：模块化优先

适合：

- 人物身体；
- 人物骨架；
- 服装接口；
- UI组件；
- 建筑结构语法；
- 动画母库；
- 昼夜/光照状态接口。

AI可以生产模块和候选，不应每次重新发明整体结构。

## 13.3 人物生产

不建议：

> 100个人 = AI自由生成100套完整人体 + 100套动画。

倾向：

> 少量标准身体/骨架家族  
> × 发型/服装/装备/饰品模块  
> × 动作母库  
> × 年龄/体型/性格修饰  
> × 少量身份专属动作。

Spine 是生产技术，不是动画语言；具体Skeleton数量和Skin结构待技术验证。

## 13.4 建筑生产

AI生成整栋房子的速度很快，但长期Village不能变成“互不兼容的建筑图库”。

倾向先建立：

> **Building Grammar / 建筑语法**

包括：

- 视角；
- 墙体厚度；
- 屋顶结构；
- 门窗比例；
- 明暗面；
- 材质简化；
- 接地方式；
- 光照接口；
- 装饰密度。

AI在语法内生成变化，而不是每栋房重新定义世界。

## 13.5 UI生产

AI适合：

- 风格探索；
- 图标方向；
- 框体候选；
- 装饰图形语言。

最终正式UI必须进入组件系统：

- 统一按钮；
- 统一状态；
- 统一间距；
- 统一字体；
- 统一面板层级；
- 可扩展布局。

不采用“每个页面让AI重新画一张完整UI图”的生产方式。

## 13.6 Source Asset ≠ Final Runtime Asset

AI输出首先是生产原料，不默认等于最终游戏资产。

建议长期链：

> AI Output  
> → Source Art  
> → Review / Standardize  
> → Rig / Slice / Mask / Variant  
> → Production Asset  
> → Runtime Binding。

## 13.7 光照与资产解耦

正式源素材不应把强烈白天/黄昏/夜晚环境光全部烘死在一张图中，否则昼夜系统难以统一。

基础资产主要说明“它是什么”；运行时或状态层负责“它现在处于什么环境”。

## 13.8 AI时代最重要的资产不是Prompt，而是约束

Visual Bible 最终不仅给人看，也应该逐渐变得“AI可读”。

例如未来需要比“像恶果之地”更准确地描述：

- 固定视角；
- 大色面优先；
- 微纹理低；
- 中尺度结构丰富；
- 暗部不丢轮廓；
- 背景透明规范；
- 光照方向；
- 角色比例区间；
- 身体接口；
- Pivot / Canvas / Scale规则。

# 14. Village / Battle / Journey 的视觉职责

## Village

当前视觉主舞台。

承担：

- 共同体；
- 人口生活；
- 建筑与布局；
- 长期变化；
- 发展感；
- 玩家自己的“家”。

因此最值得投入长期视觉系统。

## Battle

主要承担：

- 清晰角色与怪物；
- 阵列/站位；
- 战斗动作；
- 反馈；
- UI信息；
- 身份与构筑表达。

不要求像Village一样承担最大量的环境视觉叙事。

## Journey

主要是：

> 人物固定位置行走动画 + 远近景视差滚动 + 功能UI + Event连接。

是连接Battle/事件的表现载体，不是可自由探索的3D世界，也不应被错误提升为全项目视觉主舞台。
