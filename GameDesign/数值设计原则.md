# 数值设计原则

> 状态：GameDesign V0.2 数值治理原则。本文件不复制 Battle 规则、测试基线或尚未冻结的正式数值。

## 一、数值职责

- GameDesign 说明数值服务的体验与取舍。
- GameSpec 记录当前可执行规则、公式、边界和配置项。
- 数据表与配置资产保存实现使用的具体值。
- 测试值只证明行为可验证，不自动成为正式设计值。

Battle 当前数值统一以 [GameSpec/Battle/](../GameSpec/Battle/) 及其配置来源为准。本文件不重新定义行动力、抽牌、HP、恢复、距离、状态或奖励数值。

## 二、当前长期成长原则

人物等级表示成长阶段，不自动增加基础 HP、Attack 或 Range。长期成长主要扩大 Starter、Unlocked Pool、Trait 和未来组合的可能性。

因此旧“升级后获得 HP / Attack 属性点”的表格已被替代，不再是 Current 数值规范。人物最终是否存在其他基础属性变化来源，必须由后续专项设计明确。

## 三、配置化与可追溯

1. 会影响玩家策略或长期结果的数值必须来自明确配置，并能追溯至所属规则与领域来源。
2. 同一数值不得在 GameDesign、GameSpec、代码和 UI 中各自维护不同默认值。
3. 视觉坐标、Transform 与 RectTransform 不参与玩法数值关系。
4. 未冻结数值必须显式标记为测试基线、候选或待设计，不得省略状态。
5. 数值调整不得越过已经确认的设计职责，例如用基础属性膨胀替代可能性成长。

## 四、已降级的旧数值结构

以下旧口径不再是 Current：

- 固定 16 张角色牌与 16 张道具牌；
- 旧个人行动力、TP 与 Death's Door 概率；
- 角色升级获得 HP / Attack 点数；
- 固定食物、木材、石材、金币四资源；
- 旧建筑消耗、舒适度和“下一天”公式；
- 全局声望、英雄声望与套牌解锁数值。

这些内容只可用于历史追溯，不得作为新实现默认值。

## 五、仍未冻结的正式数值

当前尚未冻结的范围包括但不限于：

- 经验曲线、等级上限和主动升级条件；
- Starter Slot 上限、解锁节点与调整机会；
- 熟练上限、速度与效果；
- Trait 强化节点与效果；
- Unlocked Pool 规模、分组与候选权重；
- 领悟阈值、奖励候选数量与卡牌成长数值；
- 不同返程结果的保留与损失；
- 村庄时间倍率、资源、趋势、事件与建设数值；
- 正式篇章数量及边界；
- 装备、政策、文化与跨存档 Meta 的全部数值。

任何实现阶段需要这些值时，应先确认其规格状态；可以使用明确标记的测试配置，但不得反向写成本文件的 Current 设计值。
