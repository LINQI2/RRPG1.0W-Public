# 05 Cards

> 状态：GameDesign V0.2 当前卡牌设计意图。Battle 中的可执行牌库、抽牌、弃牌、消耗和目标规则由 [GameSpec/Battle/](../GameSpec/Battle/) 定义；Person / Profession / Growth 相关规则（Starter、Unlocked Pool、Run Copies 归属）以 [GameSpec/Person/](../GameSpec/Person/) 为可执行入口。

## 5.1 卡牌的整体职责

卡牌同时连接三个时间尺度：

1. 人物长期塑形：决定具体人物未来可能出现哪些角色牌。
2. Run 构筑：决定本次远征实际获得哪些副本并形成什么组合。
3. Battle 决策：把人物、队伍与当前局势转化为可执行行动。

长期构筑不等于永久保存完整 Run Build；Run 随机性也不能抹掉人物长期差异。

五个角色方向的卡牌与 Trait 内容候选入口见 [Identity 角色内容设计专题](Identity/README.md)。专题 [XLSX 工作台](Identity/Identity角色内容设计工作台.xlsx) 是候选卡牌/Trait 的 ID、状态、阶段、费用、触发、目标、效果、数值、持续时间与频率的主编辑源，但它不是 Runtime 配置，也不与 `Development/Excel/*.csv` 建立自动导入或覆盖关系；专题 Markdown 只维护角色语义、母题、体验、边界和 Prototype 问题，不形成第二套参数源。五个角色、36 张卡牌、4 个 Trait、6 个 Build Seed 均不是 Current Rule。“可进入 Prototype”只表示下一设计验证 Gate；Prototype 的开发、实现或导入仍需独立授权。

## 5.2 两类卡牌

### 角色牌

角色牌绑定具体人物，并读取该人物的属性与状态。它表达“这个人如何行动”，也是 Starter 与个人 Unlocked Pool 的主要内容。

### 通用牌

通用牌服务全队共享牌库，不要求机械绑定某个执行人物。它可以承载队伍协作、战术或其他通用行为。

> **正式顶层类别只有角色牌（Character Card）与通用牌（Common Card）两类。**

即使某张通用牌的内容表现是药剂、炸弹、工具或卷轴，它仍然只是通用牌的内容，不建立 `Item Card` 类型、Item Deck、Item Hand、TP 或 Battle Item System。通用牌的长期来源、Starter 来源、Run 来源、正式子分类、数量与权重仍未冻结。

角色牌与通用牌共同组成 Shared Deck。它们不是旧“上阵凭证牌堆”和“独立道具牌堆”的延续。

## 5.3 Starter

Starter 决定具体人物每次 Run 带入共享牌库的起始角色牌副本。

当前设计语义：

- 1 个 Starter Slot 对应 1 张起始副本；
- 同一卡牌模板可以重复占用多个 Slot；
- Starter 在长期成长机会中调整；
- Starter 不允许在每次远征前无成本自由重构完整牌组；
- 当前 Starter 可以积累熟练，换出后不永久保存高级熟练。

人物侧完整规则见 [04 Person.md](04%20Person.md)。

## 5.4 Unlocked Pool

Unlocked Pool 是该具体人物**当前已解锁**、可以进入长期成长与 Run 奖励候选的角色牌集合；它与职业的 Full Card Pool（理论允许完整集合）分离，普通长期成长与 Run 候选只用已解锁池（可执行规则见 [GameSpec/Person/](../GameSpec/Person/Person-Profession-Growth-GameSpec-V0.1.md)）。

村庄、事件和人物成长可以扩展同一 Unlocked Pool，但不得各自制造互不相通的平行牌池。牌池大小、分组、权重和解锁条件均未冻结。

## 5.5 Run Copies

Run Copies 是本次远征实际进入构筑的卡牌副本，来源可以包括：

- Starter 提供的起始副本；
- Run 内卡牌奖励；
- 其他由未来规格确认的远征内来源。

Run Copies 服务本次远征，Run 结束后实际 Build 默认重置。安全返程带回的是长期收益、人物成长机会与未来可能性，而不是原样永久保存整套 Run 牌组。

## 5.6 长期构筑与 Run 构筑的分工

| 层级 | 玩家塑造的内容 | 主要体验 |
|---|---|---|
| 长期人物构筑 | Starter、Unlocked Pool、Trait 与成长方向 | 可追踪、可承诺的具体人物差异 |
| 村庄长期构筑 | 扩展未来卡牌、训练控制和内容条件 | 共同体选择改变未来可能性 |
| Run 构筑 | 本次远征取得的实际副本与组合 | 随机适应、临场取舍与意外化学反应 |
| Battle 执行 | 当前共享牌库、手牌与行动资源 | 清晰的即时战术选择 |

## 5.7 历史内容母题：A1-A4 / B1-B4

A1-A4 / B1-B4 不删除，但降级为历史内容母题与未来扩展参考。它们不再冻结套牌数量、卡牌数量、稀有度、英雄选择关系或奖励池排除规则。

| 历史编号 | 内容母题 | 可保留的设计基因 |
|---|---|---|
| A1 | 村庄 | 村民身份、乡亲关系、团结互助与日常生活 |
| A2 | 械斗 | 内部冲突、秩序形成与共同体代价 |
| A3 | 驭兽（Legacy / Historical Candidate） | 仅保留人与环境生物互动的历史设计基因 |
| A4 | 警戒 | 外部威胁、守望与共同体边界 |
| B1 | 思想 | 观点形成、共同理解与分歧 |
| B2 | 信仰 | 意义、信念、凝聚与服从之间的张力 |
| B3 | 知识 | 求证、方法、积累与挑战既有认知 |
| B4 | 精神 | 个体内在、质疑、意识与共同体关系 |

这些母题未来是否仍按八组、如何分层、由谁承载，均未冻结。

A3「驭兽」来自旧 PVP 版本，高度依赖生物卡、九宫格、暗置 / 唤醒与空间互动。当前单人 Battle 尚未确认生物卡或驭兽系统，因此 A3 只保留“人与环境生物互动”的历史设计基因，不作为 Current 内容路线、正式复杂度阶段或章节承诺。

## 5.8 已替代与未冻结

已被替代的旧承载：

- 固定 16 张角色牌 + 16 张道具牌；
- 角色牌作为上阵凭证；
- 独立 `Item Card` 牌堆、独立道具手牌与旧 TP 费用关系（旧兼容展示不代表该产品身份恢复；旧实现进入 Legacy Cleanup Candidate，代码尚未清除）；
- 套牌稀有度作为固定结构；
- 由英雄选择套牌；
- 未选择套牌就完全不进入奖励池。

仍未冻结：

- Unlocked Pool 的正式规模与分组；
- Run 奖励候选数量、权重与正式数值；
- A1-A4 / B1-B4 的最终内容结构；
- 通用牌的正式子分类；
- 卡牌成长、熟练与村庄扩池的全部数值。
