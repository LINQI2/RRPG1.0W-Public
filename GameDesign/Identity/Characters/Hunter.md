## 1. 身份锚点（Identity Anchor）

Hunter 来自长期追踪、等待、判断和捕获猎物的经验。进入 Battle 后，不把它压缩成“条件增伤职业”，而是把战场中的公开 Fact 视为会短暂出现、需要判断价值的**机会窗口**。

## 2. 战斗身份（Battle Identity）

> **识别并捕获机会。**

玩家反复判断：

- 当前哪一个 Fact 真的是机会；
- 多个机会同时出现时先抓哪个；
- 是现在兑现，还是等待更高价值窗口；
- 自己捕获还是把机会交给队友；
- 机会是否值得持续追踪。

Hunter 的核心体验不是持续变大，而是：**“就是现在。”**

## 3. 母题 / 子题候选地图

### 识别
- 状态机会
- Intent 机会
- 位置机会
- 关系机会
- 机会变化
- 多条件高价值机会

### 选择
- 目标优先级
- 高价值 vs 高把握
- 当前机会 vs 潜在机会
- 旧猎物 vs 新机会
- 自己捕获 vs 队友捕获
- 选谁协猎
- 用谁的能力

### 追踪
- 持续锁定
- 观察历史
- 痕迹累积
- 换猎物 / 切换成本
- 多目标追踪
- 主动巡猎
- 熟悉猎物

### 捕获
- 直接攻击
- 攻击质量
- 行动效率
- 获得更多选择
- 利用他人能力
- 让队友利用机会
- 独自捕获
- 围猎捕获
- 保存 / 延迟机会
- 不同结果转换

“捕获”不是 Damage 的同义词；它可以把机会转换为 Damage、Draw、行动效率、位置或其它战斗价值。

## 5. 构筑接口

主要开放接口：

- HP；
- Enemy Intent；
- Timing；
- Target；
- Position / Adjacency；
- 独狼 / 群羊；
- 可读的短时机会窗口。

Hunter 的职责是**读取与转化机会**，不应成为“所有 Battle Fact 满足条件就 +Damage”的万能出口。

## 6. 构筑种子与体验候选

### 机会兑现（候选）

体验骨架：

> 观察 → 多个机会竞争 → 捕获正确窗口 → 高价值兑现

当前优势主要来自**机会质量与行动效率**，而非长期数值堆叠。

### 创造机会 → 捕获机会（涌现 Seed 候选）

Worker 改变 Position / Adjacency / 独狼 / 群羊后，可能主动制造 Hunter 原本需要等待的空间机会；Hunter 再判断是否值得捕获。

这属于 Shared Deck 的涌现组合，不属于 Worker 或 Hunter 的固定职业流派。

### 连续猎杀

仅为后续体验候选。当前内容主要证明“抓准一个机会”，尚不足以宣称 Hunter 已形成连锁猎杀 Build。

## 7. 内容阶段原则

早期优先：

- HP；
- Intent；
- 简单 Position / 独狼；
- 可直接看到的目标机会。

中后期再开放：

- 群羊 / 更复杂关系机会；
- 主动巡猎；
- 持续追踪；
- Current Prey / Focus 等显式关系候选。

若需要长期追踪，必须有系统可视承载，不能要求玩家自己记“上一个猎物”。

## 8. 组合观察

Hunter 很适合作为其它系统制造出来的机会的兑现者：

- Worker：创造空间机会 → Hunter 捕获；
- Cook：准备手牌 / AP → Hunter 在短窗口集中兑现；
- Farmer：培养高价值 → Hunter 选择收割时机；
- Herbalist：状态 / 风险变化可能改变目标机会，但不能退化成“有 Status 就加伤”。

## 9. 原型验证 / 开放问题

1. Opportunity 的真实出现频率是否足够，但又不是常驻？
2. 玩家能否快速读出“这就是机会”，而不靠大量文本计算？
3. 《应对攻击》的抽牌频率是否可能形成过强循环；现在不提前加 Frequency 限制。
4. 持续追踪是否真的值得新增 Current Prey / Focus Relation；只有多个强设计共同需要时才引入。

## 10. 当前边界

- Current：识别 / 选择 / 追踪 / 捕获四母题；机会兑现体验；公开 Battle Fact 是机会来源。
- 开放：持续 Focus、连续猎杀、最终 Trigger 频率与数值。
- 禁止误解：Hunter ≠ 条件增伤合集；捕获 ≠ 只能造成伤害。
