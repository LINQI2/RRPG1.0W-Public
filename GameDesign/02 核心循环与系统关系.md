# 02 核心循环与系统关系

> 状态：GameDesign V0.2 当前循环设计，2026-08-31 收口。
> 2026-09-07 FP-V0.1 归位同步：补充 FP-V0.1 产品循环与 Battle-first 上手方向（§2.7），仅产品层轻量同步，不含技术实现细节。

## 2.1 总体核心循环

RRPG 的总体循环是：

> 塑造条件 → 组织行动 → 远征 → 承担结果 → 安全返程与消化 → 世界变化

这个循环连接村庄、人物与战斗，而不是把它们拆成三个独立模式。

## 2.2 六个阶段

### 1. 塑造条件

玩家观察村庄趋势、人物状态和已经打开的未来可能性，决定当前共同体能承受什么。

### 2. 组织行动

玩家选择远征目标与出发人物，并在长期成长机会中调整人物 Starter。完整牌组不能在每次远征前自由重构。

### 3. 远征

人物进入远征推进旅程（Node-based Progression），在战斗、事件与其他遭遇中形成 Run 内构筑，积累风险、领悟与暂存收益。

### 4. 承担结果

HP 跨战风险、路线选择、资源消耗和人物遭遇共同形成后果。不同结束方式应产生不同损失与保留结果，具体数值仍未冻结。

### 5. 安全返程与消化

安全返程把远征中的暂存经验、金币、材料或其他收益转换为长期结果。人物成长、牌池扩展与村庄变化在这一阶段得到可追踪的落点。

### 6. 世界变化

时间继续推进，长期世界事实形成可感知的 Pattern；其中具有决策意义的，经合理的人物或共同体感知与表达后，进一步形成 Event / Consequence，过去的承诺改变人物、村庄和下一次远征的条件。

## 2.3 村庄五步循环

村庄内部使用以下循环：

> 观察 → 选择优先级 → 作出承诺 → 推进时间 → 后果显现

它不是独立于总体循环的另一套游戏，而是“塑造条件”和“世界变化”的主要交互形式。时间、趋势、社会决策维度与复杂度阶梯详见 [07 Village.md](07%20Village.md)。

## 2.4 远征内循环

远征负责：

1. 在不确定节点中选择路线与风险；
2. 以人物 Starter 和 Unlocked Pool 为长期基础；
3. 通过 Run Copies、领悟与奖励形成短期构筑；
4. 让人物 HP、经历与暂存收益产生跨节点压力；
5. 通过安全返程或其他结束方式结算长期后果。

Battle 的回合、共享行动力、抽牌、弃牌和胜负规则由 [GameSpec/Battle/](../GameSpec/Battle/) 定义，本文件只说明其在总循环中的职责。

## 2.5 长期塑形反馈

长期进度不以“获得永久更高数值后重复相同选择”为核心，而是形成以下反馈：

> 远征经历与收益 → 人物 / 村庄获得新的长期可能 → 下一次组织行动更有方向 → Run 中出现新的组合与后果

人物长期成长见 [04 Person.md](04%20Person.md)，卡牌长期与 Run 职责见 [05 Cards.md](05%20Cards.md)，远征结算见 [06 Expedition.md](06%20Expedition.md)。

### History × Autonomous Life 横切反馈（Current Architecture）

> 2026-10-04 归位：Autonomous Life Vertical Slice V0.1 的产品方向已批准。本文只登记跨系统长期职责；具体可执行行为规则见 `GameSpec/Village/Village-GameSpec-V0.1.md`，技术承载见对应 Technical Architecture / DevelopmentSpec。Utility 公式、Relationship 数值、具体类名与字段不在此冻结。

```text
World / Person / Place 提供可行 Activity
↓
Person 根据自身差异、Directional Relationship（有方向关系）与当前 Context 作出自主选择
↓
Activity 完成形成 ephemeral occurrence；按语义投影为 0 或 1 Canonical Relational Fact
↓
Fact 被不同 Consumer 按职责解释
├─ Relationship Interpreter → 当前 Relationship State → Future Behavior
├─ Recognition Projection → Event
└─ Historical Projection → History View
↓
新的世界状态改变未来 Possibility
↓
New Action / Fact
```

当前确认：

- History 是连接 Battle / Expedition / Village 的横切语义层，不是第四个独立玩法模式。
- `Fact（事实）` 表达“过去真实发生了什么”；`Derived State（派生状态）`表达“这些事实截至当前形成了什么状态”，二者不得混为同一 Authority。
- Battle / Expedition / Village 都可以成为合法 Fact Producer；具体领域是否已生产某类 Fact，仍以对应 Current Runtime / GameSpec 为准。
- Consumer 应优先读取“最高且足够使用”的语义层，但不得把同一历史通过 Fact / Relationship / Life Episode 重复计权。
- `Life Episode（人生经历片段）` 当前优先作为 Derived Historical Projection（派生历史投影）；不替代 `Experience（客观经历记录）`、`PersonLifeHistory（人物人生史）` 或 Formation Evidence。
- LLM 可以参与文本表达，但不拥有 Simulation Authority（模拟权威）。

完整产品规格见 [Autonomous Life Vertical Slice Product Spec V0.2](../Docs/DesignCheckpoints/2026-10-04_RRPG_Autonomous-Life-Vertical-Slice_Product-Spec-V0.2.md)。原 2026-10-02 Checkpoint 继续作为推理证据，不再代表专题当前 Freeze Level。

WP-AL-3 已确认：世界提供 Possibility、规则判断 Eligibility、人物判断 Plausibility；Utility 决定个人候选意愿顺序，分轮仲裁仅解决冲突，不做全村最大效用匹配。Decision 只读 Current State，不与 Formation 合并，也不整本扫描 History 参与 Utility；同一轮不 reroll。规则见 [Village GameSpec §12](../GameSpec/Village/Village-GameSpec-V0.1.md)，分级依据见 [WP-AL-3 Final](../Docs/DesignCheckpoints/2026-10-04_RRPG_WP-AL-3_Autonomous-Selection_Design-Checkpoint-V0.2-Final.md)。WP-AL-1/2/3已Published Main；WP-AL-4反馈已接线并发布main，具体实现归Current Architecture。WP-AL-4确认Producer只表达发生语义，Social Domain单一拥有Production Relationship Interpreter，Activity不直接改Relationship。Completion、Canonical Fact、Significant / Life Episode是不同生命周期，不设三套Ledger；较早应影响关系的Feedback须在下一Decision Snapshot前settled。规则见[Village GameSpec §12.6](../GameSpec/Village/Village-GameSpec-V0.1.md#wp-al-4-feedback)，输入见[WP-AL-4 Final](../Docs/DesignCheckpoints/2026-10-04_RRPG_WP-AL-4_Social-Feedback_Design-Checkpoint-V0.1-Final.md)；WP-AL-4 Runtime已Published Main；Recognition / LifeEpisode及完整表现仍后置。

## 2.6 与跨存档 Meta 的边界

村庄长期进度、人物成长和 Unlocked Pool 属于当前游戏世界内的长期塑形，不等同于跨存档元进度。全局声望、英雄声望、解锁英雄或解锁套牌等旧 Meta 结构尚未重新确认，统一见 [当前设计状态的 Deferred Meta 边界](当前设计状态.md#deferred跨存档-meta-progression)。

## 2.7 FP-V0.1 产品循环与上手方向

> 2026-09-07 归位：FP-V0.1（RRPG Functional Prototype V0.1）的产品层循环与上手方向。本文件不包含任何技术实现细节。

FP-V0.1 的产品循环把完整可玩骨架串成可重复循环：

```text
Village / Home
→ Expedition Prep
→ Expedition Progression
→ Battle / Situation / Reward
→ Return
→ Village / Home
→ Continue
```

第一次 Return 后仍可继续 Prep、再次 Expedition、再次 Return；核心循环可持续重复。

开局采用 **Battle-first**：先让玩家理解 Battle，再逐步揭示 Home 与 Expedition 管理。前期 Village 复杂度慢构筑，稳定内容先观察、被变量引入后才管理；相关原则见 [07 Village.md](07%20Village.md)。远征推进结构与可执行规则见 [06 Expedition.md](06%20Expedition.md) 与对应 GameSpec。
