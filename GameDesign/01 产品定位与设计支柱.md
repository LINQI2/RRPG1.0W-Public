# 01 产品定位与设计支柱

> 状态：GameDesign V0.2 当前顶层设计，2026-08-31 收口。

## 1.1 游戏概念

RRPG 是一款：

> 单人长期共同体经营 + 远征式 RPG 卡牌构筑游戏。

玩家经营的不是抽象数值面板，而是一群会积累经历、形成差异并承担后果的具体人物，以及他们共同生活、不断变化的共同体。玩家组织人物进入远征，在不确定环境中形成短期构筑；远征结果又改变人物和村庄未来能够出现的选择。

## 1.2 核心幻想

核心幻想由四部分共同组成：

1. 认识并长期塑造具体人物，而不是替换同质化单位。
2. 经营一个会因资源、关系、制度、信念与知识选择而变化的共同体。
3. 派遣人物进入远征，在风险中形成只属于本次 Run 的卡牌组合。
4. 让过去的承诺与后果改变未来可能出现的卡牌、成长、事件、遗物、能力和发展方向。

人物与卡牌产生化学反应的思想继续保留，但它现在是组合深度原则：人物身份、长期牌池与本次 Run 获得的牌共同形成打法，而不是把卡牌降级为人物之外的辅助物。

## 1.3 八条 Design Pillars

### P1 先建立基础，再追求表面简洁

系统可以从小规模开始，但必须先有能承载未来复杂度的清晰职责与关系。

### P2 复杂度持续积累，不按篇章清零

后续内容应在已有理解上增加新关系，而不是每个篇章重新开始一套互不相干的系统。

### P3 长期成长扩大可能性，而非制造数值膨胀

等级、村庄与人物成长主要改变可选择内容、组合能力与控制程度。等级不会自动提高基础 HP、Attack 或 Range。

### P4 具体人物优先于抽象单位

卡牌、Trait、经历、风险和长期选择应尽量落在可识别的具体人物身上。

### P5 系统只为有意义的选择而存在

新增资源、建筑、政策或数值前，必须先说明它让玩家看见了什么取舍。

### P6 村庄扩大未来可能性，而非硬性阻断正常成长

村庄连接战斗的主要方式，是让更多未来内容、训练控制和发展条件成为可能，而不是用设施等级粗暴锁住普通成长。

### P7 Run 随机体验与长期确定塑形分工

远征负责不确定的即时构筑；人物与村庄负责玩家可追踪、可承诺的长期方向。

### P8 先确定系统存在的理由，再确定承载形式

主题、教学目标与玩家决策先于资源名、建筑名、点数名或 UI 形式。

## 1.4 三层设计职责

| 层级 | 主要职责 | 长期输出 |
|---|---|---|
| 战斗 / 远征 | 选人、共享牌库、空间关系、Run 随机构筑、人物风险与短期资源管理 | 人物经历、可消化收益与新的未来条件 |
| 具体人物 | Starter Slots、Unlocked Pool、Trait、成长阶段与长期差异 | 更有辨识度的人物与更丰富的未来卡牌可能 |
| 村庄共同体 | 观察趋势、分配优先级、作出社会承诺并推进时间 | 扩展内容可能性、训练控制、共同体状态与世界后果 |

Battle 的可执行行为不在本文件定义，统一以 [GameSpec/Battle/](../GameSpec/Battle/) 为准。

## 1.5 内容扩展原则

- 主题与玩家理解优先于功能标签。
- 新机制必须说明其主题意义与教学理由。
- 初始内容池可以小，但必须构成完整、可玩的选择闭环。
- 后续扩展主要增加新的可能性与关系，不以永久数值膨胀替代内容深度。
- 社会复杂度应在前一层经验上累积，不通过系统清零制造“新章节”。

## 1.6 明确非目标

当前设计明确不以以下方向为目标：

- 延续旧 PvP 结构；
- 移动游戏式永久数值膨胀；
- 每次远征前自由重构完整牌组；
- 纯村庄模拟游戏；
- 战斗与村庄互不影响的两个独立小游戏；
- 通过堆叠资源、建筑和科技树数量制造表面深度；
- 按篇章重置系统复杂度；
- 只以百分比增益承载政策、文化和社会选择；
- 为政治、文化、信仰或知识问题设置唯一正确路线。

## 1.7 尚未冻结的顶层承载

英雄最终身份、正式篇章数量与边界、装备体系、政策与文化结构、人物关系机制、村庄资源和建筑列表等仍是后续专项设计内容。它们不得从旧文档或当前实现中自动恢复为 Current。
