## 1. 当前美术配置方式总览

### 1.1 直接换图
`Hierarchy / Prefab → Image → Source Image → 拖入 Sprite`

适合：Journey 大背景、Journey EnvFar / EnvNear、Battle 背景、Battle RowVisual、公共占位图。

### 1.2 Catalog 配置
`某个 .asset → Entries → Size +1 → Element → 填 Key → 拖 Sprite`

适合：当前仍采用手工 Catalog 绑定的 Person Visual、Journey Event Illustration。这是这两个领域的现行操作方式；后续生产工具按 D-019 和逐域迁移方案确认，不由内容量扩大直接推导为继续扩展手工 Catalog。

### 1.3 Prefab 共用视觉
修改一次 Prefab，所有使用它的地方一起变化。

当前主要包括：`UnitCard.prefab`、`CharCard.prefab`、`HeroSelectCard.prefab`、`BattleCard.prefab`。

### 1.4 Inspector 参数微调
常见字段：
- Scale：缩放
- Offset：偏移
- Color：颜色
- Alpha：透明度
- Spacing：间距

### 1.5 已迁移的敌方图片

在 `Development/Config/RRPG_EnemyPresentation.xlsx` 维护映射，在 `Development/SourceAssets/Enemy/` 替换源图，再运行现有一键导表流程；详细步骤见 [配置表操作说明](../../Development/Config/README.md) 和本文 §12。人工维护来源（Authoring Source）是工作簿与源图；生成镜像（Generated Mirror）及 Unity 生成资产由工具重建，不在 Inspector 中改生成资产。

## 2. PNG 导入 Unity 的通用步骤

**适用范围：仍采用手工绑定的领域。** 本节不适用于迁移分支上的敌方图片；敌方源图放在 `Development/SourceAssets/Enemy/`，并按 [配置表操作说明](../../Development/Config/README.md) 重新导表，不按下列步骤放入 `Assets/Art/` 或手工调整生成资产的导入设置。

1. 将 PNG 放入 `Assets/Art/...`。
2. 在 Project 面板选中 PNG。
3. Inspector：
   - `Texture Type = Sprite (2D and UI)`
   - `Sprite Mode = Single`
4. 点击 `Apply`。

当前原型阶段不冻结最终 PPU、压缩、Atlas、Addressables 等规范。

## 3. Person Visual｜人物图片

配置入口：

`Assets/Resources/ScriptableObjects/Presentation/PersonVisualBindingCatalog.asset`

字段：

- `Entries`：人物视觉配置列表。
- `Element`：一条人物视觉配置。
- `Appearance Key`：该行视觉配置属于哪个人物模板，例如 `person_su_wan`。它不是人物身份 Authority；人物身份仍由 `PersonId` 决定。
- `Default Body Sprite`：默认人物图片。
- `Journey Sprite Override`：Journey 专用人物图；为空时用 Default。
- `Battle Sprite Override`：Battle 专用人物图；为空时用 Default。
- `Prep Sprite Override`：准备 / 选人卡专用人物图；为空时用 Default。
- `Hero Select Sprite Override`：Hero 选择界面专用人物图；为空时用 Default。
- `Scale`：缩放；1=原比例，0.8=80%，1.2=120%。
- `Offset`：偏移；X 正右负左，Y 正上负下。

推荐新增人物时第一次只填：
- `Appearance Key`
- `Default Body Sprite`

其余 Override / Scale / Offset 先保持默认，再进 Expedition Prep / Journey / Battle 验证。

配置安全：
- 空 AppearanceKey 不参与解析并告警；
- 重复 AppearanceKey 明确告警；
- 重复 Key 保留第一条生效；
- 不自动删除或修改制作人配置；
- 找不到配置走既有 fallback / placeholder。

## 4. Journey 大背景

`BackgroundHost → Image → Source Image`

当前 `Preserve Aspect` 关闭，因此会填满区域；宽高比差异过大时会拉伸。第一版建议接近 16:9，但不是最终素材规格冻结。

## 5. Journey EnvFar / EnvNear

Hierarchy：

- `ExpeditionJourneyRoot → EnvironmentHost → EnvFar`
- `ExpeditionJourneyRoot → EnvironmentHost → EnvNear`

含义：
- EnvFar：远景层，例如远山、天空、远处森林。
- EnvNear：近景层，例如草、石头、道路、前景装饰。

配置：
`Image → Source Image`

当前 EnvNear 移动较快、EnvFar 较慢，用于视差滚动。当前白模尺寸不是正式素材规格。

## 6. Journey Event Illustration｜逐事件插图

正式统一Event：在RRPG_VisualAssets.xlsx维护VisualAsset，源图放Development/SourceAssets/Event；RRPG_Events.xlsx / EventPresentation.IllustrationAssetId引用共享ID。经同一Compiler / Builder生成，不在Scene、Prefab或Legacy Catalog重复配置。完整制作限制见[配置手册](../../Development/Config/README.md)。当前正式Event插图内容仍为空，不因已有接线而视为美术已完成。

Battle前卡与Branch类别fallback保留JourneyEventPresentationCatalog的Legacy / Compatibility接线；NodeId仅此范围的临时表现键，不等于EventId或EncounterId。Inspector步骤见[兼容插图手册](2026-09-19_RRPG_Journey-Event-Illustration-Binding-V0.1_Manual-Configuration-Guide.md)。

## 10. Battle 六排 RowVisual

我方：
- `playerFrontRow`
- `playerMiddleRow`
- `playerBackRow`

敌方：
- `enemyFrontRow`
- `enemyMiddleRow`
- `enemyBackRow`

每个 Row Root 下都有：
`RowVisual`

它是纯表现层，不是 Row / Column Authority。

换图：
`RowVisual → Image → Source Image`

### 自动 Tint
BattleUI 当前存在：
`Row Visual Tint Enabled`

开启时我方偏蓝、敌方偏红。如果彩图发蓝 / 发红 / 发灰：
1. 关闭 `Row Visual Tint Enabled`；
2. 确认 RowVisual 的 `Image → Color` 接近纯白。

安全边界：
可以改 RowVisual 的 Sprite / Color / RectTransform；不要为了美术随意改六个 Row Root 的位置 / 大小，因为这些 Root 参与 Battle Hit Test / Formation 映射。

## 20. 操作安全等级

下列 PNG 导入、拖 Sprite、编辑 Catalog 等操作只适用于各章节明确仍采用手工绑定的领域。已迁移的敌方图片使用 [配置表操作说明](../../Development/Config/README.md) 的 XLSX／SourceAssets 入口；换图后重新导表，生成 JSON 与 Unity 生成资产不人工编辑。

### 🟢 可以自行操作
- PNG 导入
- `Image → Source Image`
- Catalog 新增 Element
- Catalog Sprite
- Catalog Scale / Offset
- Journey Background
- EnvFar / EnvNear
- BattleBackground
- RowVisual
- 公共 placeholder 图标

### 🟡 可调整，但建议先截图 / 备份
- Prefab 内视觉子节点
- Body_Visual RectTransform
- RowVisual RectTransform
- BattleCard Image_Art
- 卡框
- 文字位置
- UnitCard Anchor_* 视觉节点

### 🔴 不要仅为了美术随意修改
- 六个 Battle Row Root
- BattleController Gameplay 字段
- Row / Column Authority
- PersonId
- CardId
- Runtime Script
- Button Root
- Canvas 生命周期
- 删除 / 改名当前绑定 GameObject

如果必须修改这些才能完成视觉，应停止并转开发审计。

## 22. 什么时候回到开发线

以下情况属于生产接口问题：
1. 不同内容需要不同图片，但只有一个公共槽；
2. 必须改代码才能换图；
3. 改视觉导致 Gameplay / Hit Test / Raycast 失效；
4. 现有工作簿、导表工具或手工绑定接口不能表达新的内容需求，需要按 D-019 另行确认该领域的迁移方案；
5. 需要新增批量内容 Binding；
6. 需要自动生成 / 更新大量 Catalog 条目。

## 23. 长期方向

长期静态内容制作方向以 [决策记录 D-019](../决策记录.md) 和 [技术架构总览](../Architecture/技术架构总览.md) 为准：

```text
XLSX + Source Assets（按内容需要的人工来源）
→ Config Compiler
→ Canonical JSON / Asset Manifest（生成镜像）
→ Unity Builder（生成数据库、Catalog 与受管理资源）
→ Definition / Registry 与资源解析入口
→ 游戏与 UI 消费者
```

当前按领域使用：

- Monster Definition / Enemy Presentation：迁移分支已完成 M0–M4；敌方三张源图仍是临时素材，正式美术未验收。
- Person Visual / Journey Event Illustration：继续按本手册对应章节使用现有手工 Catalog；尚未因此进入上述批量配置链。
- Battle Card Art、Biome、正式 Event Content 等其它领域：先核对现有实现、内容定义与适用规则，再确定是否及如何迁移；本节不指定下一开发任务。

旧 [美术批量导入与 Art Import Skill 规划](2026-09-20_RRPG_美术批量导入与Art-Import-Skill规划_V0.1.md) 已标为 **SUPERSEDED / DO NOT IMPLEMENT**，仅用于追溯，不再把其中的 Art Batch Import Pipeline 当作下一生产工具方向。

## 24. 本手册维护规则

当以下事项发生实际变化时同步更新本文件：
- 新增美术配置入口；
- Catalog 字段变化；
- Prefab / Scene Host 路径变化；
- 某类素材进入批量生产；
- 新增自动导入工具；
- 某一白模表面升级为正式产品表面；

本文件只记录已可使用的生产入口。

尚未实现的规划进入独立 Planning / Development Spec，不伪装成当前可操作功能。
