# 引擎场景层级与配置查找指南

> 2026-10-04，按当前 Unity / 团结编辑器的 `Assets/Scenes/SampleScene.scene` 回读整理。面向制作人的操作指南；不是玩法或新的架构 Authority。本轮已获收尾发布授权，实际提交与远端同步状态查最终交接和Git。
> 工程目录：`UnityProject/RRPG1.0game/`。下面的 `Assets/...` 均是该工程内路径；Hierarchy 路径从场景根对象开始。

## 当前运行时入口补充（不改写2026-10-04场景快照）

D最小现场面板由VillageWorldLayer运行时建立：从正常Town路径打开现场、选人查看实际地点/通勤/工作/来访与本人中断；关闭面板不停止模拟，重开继续读取实际状态。它不是已经作者化的完整空间实体/Camera。返程期间Pending Event使用VillageSocialEventUI的阻塞overlay，处理并关闭结果后续原推进请求；不能仅因TownCanvas隐藏判断事件不可见。以上是已验收Runtime路径，静态Hierarchy以下仍按原回读日期；新视觉任务须重新回读Editor。

## 1. 找到一个界面的基本步骤

1. 在 Project 窗口找到 `Assets/Scenes/SampleScene.scene`，打开场景。
2. 在 Hierarchy 展开 `SceneUIHosts`，选择所需界面，例如 `BattleController`。
3. 右侧 Inspector 查看它的业务组件；要调整界面位置 / 图片 / 字体，再展开其 Canvas，选择具体子对象。
4. 配置字段右侧的对象引用可以点击定位；双击引用的 Prefab / 配置资产，查看 Project 中的原始资源。对象选择按钮用于查看或换绑引用。
5. 修改持续使用的卡牌外观，应进入其 Prefab；运行时生成的卡片只适合观察，停止 Play 后会消失。

Hierarchy 搜索框可以输入 `BattleController`、`VillageHUD`、`HUD_ActionPointText` 等具体名字。搜索后仍要确认完整父级：不同界面可能有同名 Label、InfoText、Image。选中对象后按 F 聚焦 Scene 视图；在 Game 视图正常游玩查看最终显示。

Inspector 普通显示找不到某个内部字段时，组件右上角菜单可切 Debug 查看真实字段名；绑定先观察，避免直接换绑。本文表格同时给出实际字段名与部分自定义 Inspector 标签。

## 2. 为什么层级这样分

```text
SampleScene
├─ Main Camera                相机与音频监听
├─ EventSystem                鼠标 / 键盘与UI输入
├─ SceneUIHosts               常驻的界面收纳目录
│  ├─ MainMenuUI
│  ├─ HeroSelectionUI
│  ├─ TownUI
│  ├─ CharacterGrowthUI
│  ├─ DeckViewerUI
│  ├─ ExpeditionUI
│  ├─ BattleController
│  ├─ MapUI
│  ├─ BattleResultUI
│  ├─ ShopUI
│  ├─ RecruitUI
│  ├─ EventUI
│  └─ RunRewardUI
├─ VillageTimeDriver          村庄时间驱动
└─ ExpeditionJourneyRoot      旅途画面与协调组件
```

`SceneUIHosts` 只有 Transform，负责把原来的界面放到容易观察的位置；它不负责开关全游戏。每个界面的业务组件负责自己的数据与显示，下面的 Canvas 装图片、文字和按钮。不要通过关闭 SceneUIHosts 退出某个界面。

旅途根本身就是 Canvas；时间驱动、相机与输入保留顶层，让它们的生命周期不受某个界面开关影响。层级表示编辑与显示组织；人物身份、战斗规则、村庄时间、存档状态各有自己的代码与数据 Authority，不由图片父子关系决定。

灰色对象通常是当前流程尚未打开，不一定是废弃。编辑器 activeSelf 与运行后实际可见也不同：父对象隐藏时，子对象即使勾选仍不可见。

## 4. 战斗：改哪个配置，去哪里找

先选中 `SceneUIHosts/BattleController`。它不是只挂一个 Controller，而是挂三个配合工作的组件：

| 要调整什么 | Inspector 组件与分组 | 字段 / 显示标签 |
|---|---|---|
| 我方 / 敌方单位牌大小 | BattleUI → Unit Presentation | unitCardScale / Player Unit Scale；monsterCardScale / Monster Unit Scale |
| 战前人物准备牌大小与间距 | BattleUI → Prep Character Hand | prepCardScale、prepHandCenterOffset、prepHandBaseStep、prepHandMinStep |
| 排内1 / 2 / 3人位置 | BattleUI → Formation Presentation | singleUnitVisualOffset、twoUnitVisualSpacing、threeUnitVisualSpacing、rowLocalVisualOffset |
| 拖动预览偏移 | BattleUI → Formation Presentation | dragPreviewOffset |
| 选牌、命中、数字变化的节奏 | BattleUI → Combat Feedback | feedbackEnabled、Feedback Profile 展开后的各项时间 / 距离参数；这是内嵌配置，不是独立 Profile.asset |
| 背景、身体图、Intent占位等 | BattleUI → Advanced Presentation — Body / Background / Intent | battleBackground、playerBodyPlaceholder、Intent / Shield 占位及比例字段 |
| 正式行动牌大小 / 扇列间距 / 中心 | BattleV1Runtime | Battle Card Base Scale、Hand Base Step、Hand Min Step、Hand Center Offset |
| 行动牌按数量缩小 | BattleV1Runtime | Scale By Count、Minimum Scale (Ratio)；关闭按数量缩放时用 Base Scale |
| 回合 / 抽牌 / 弃牌数字格式 | BattleHudPresenter | turnFormat、drawPileFormat、discardPileFormat 及对应 Host |
| 现有行动力 / 每回合抽牌参数 | BattleV1Runtime → Internal — Bindings / Existing Rule Configuration | maxActionPoints、baseDrawCount；属于玩法参数，按当前规则另行确认 |
| 准备牌 / 单位牌 Prefab与排绑定 | BattleUI → Internal — Scene / Prefab Bindings | prepCardPrefab、unitCardPrefab、六排字段；部分内部字段需 Debug查看 |
| 行动牌 Prefab / 容器绑定 | BattleV1Runtime → Internal — Bindings / Existing Rule Configuration | battleCardPrefab、handContainer |

不要在运行时调整一张生成牌的位置来解决所有手牌排列。手牌与排内位置会被布局代码重算，应修改上表中的配置。

```text
SceneUIHosts/BattleController/BattleCanvas
├─ BattleBackground
├─ Row
│  ├─ playerFrontRow / playerMiddleRow / playerBackRow
│  └─ enemyFrontRow / enemyMiddleRow / enemyBackRow
├─ PrepCharacterHandRoot      战前人物 / 英雄准备牌、拖拽暂存
├─ BattleActionHandRoot       战中行动牌
├─ BtnStartBattle / BtnCancelOp / BtnEndTurn
├─ TurnRoot                  HUD_TurnText、TurnFrameImage、TurnBackdropImage
├─ ActionPointRoot           HUD_ActionPointText、Circle_BG、Circle_Fill
├─ DrawPileRoot              HUD_DrawPileText、DrawPileImage
├─ DiscardPileRoot           HUD_DiscardPileText、DiscardPileImage
├─ HudDecorationRoot         DecorationImage
├─ BtnSettings / BtnParty
└─ InfoText                  隐藏调试与兼容宿主
```

六排承接规则映射和生成单位牌；行内图片只负责美术。前排 / 中排的 RowArtwork 是原图片的新名字；其它排仍有 `Image (1)` 等带编号美术名字，本轮没有把它们全部统一命名。RowVisual 是透明的可选色块；Text_Left / Center / Right 是隐藏开发标签，工具仍按名字读，保留。

HUD绑定：BattleHudPresenter 的 turnHost / drawPileHost / discardPileHost 分别指向上面三个数字文本；行动力由 BattleV1Runtime.txtSharedActionPoint 指向 ActionPointRoot/HUD_ActionPointText。换底图选 Image 的 Source Image；换数字字体 / 外观选 TextMeshProUGUI；不要把图片对象当成数字状态来源。

BtnStartBattle / BtnCancelOp / BtnEndTurn 的文字在子对象 Label。BtnSettings / BtnParty 目前的文字仍叫 Text (Legacy)，实际组件已是 TMP；名字不代表已实现完整设置 / 队伍功能。按钮用途和监听需以实际组件 / 代码为准。

## 7. 为什么编辑后可能没有变化

- 改的是场景模板，而显示对象是另一份Prefab实例：沿业务组件的引用定位原资源。
- 改了位置，进入Play被布局重算：改宿主的间距 / 缩放参数。
- 改了运行时副本，停止Play丢失：退出Play后在Scene / Prefab / 配置资产修改并保存。
- 对象自己勾选，但父级隐藏：从父Canvas / 业务宿主检查实际显示链。
- 某些按钮 OnClick 看着空：业务代码可能在运行时注册。不要为了“补齐”重复绑定。
- 改了生成数据库：下一次导表会覆盖。回到XLSX / 源图入口。
- 找到一个旧商店、旧地图或旧事件界面：它的存在不代表当前正常流程使用它。

Scene / Prefab中的显示与绑定用Editor修改，保存前退出Play。不要通过批量删除隐藏对象或随意换父级来调整界面，那里可能仍有名称查找和拖拽坐标依赖。

## 8. 验收这份指南

可以只做查找，不需要修改配置：

1. 按 §3 找到主菜单、村庄、出征、战斗、结算和旅途画面。
2. 在 BattleController 找到准备牌与行动牌的两组大小 / 间距配置，并确认是不同组件。
3. 定位4个Battle数字HUD、村庄日期、旅途事件卡片。
4. 找到CharCard / UnitCard / BattleCard三个模板，以及统一字体配置资产。
5. 确认隐藏兼容对象没有被当成废物删除，停止Play后场景仍保存完整。

本指南是配置入口说明，不要求制作人验收代码、存档事务或全部引用链。技术证据见[架构优化总结与验收清单](DevelopmentSpecs/2026-10-04_RRPG_架构优化总结与验收清单.md)。
