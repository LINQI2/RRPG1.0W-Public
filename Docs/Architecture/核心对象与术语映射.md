# 2. Person / Character / Hero / BattleUnit

## 2.1 核心对象映射总表

下表是代码对象、生命周期与所有权的速查，详细职责沿用后续专题章节；不重复 GameSpec 公式。

| 中文概念 | 正式代码对象/标识 | 生命周期 | Authority | 禁止混用 |
|---|---|---|---|---|
| 具体人物 Person | `CharacterInstance` / `HeroInstance`，以 `PersonId` 贯通 | 长期 | 对应长期实例；无统一 Person 实体类 | 模板、卡、BattleUnit 不等于 Person |
| 战斗兼容定义 | `CharacterData`（ScriptableObject） | 配置；实例保留 CharacterId 兼容引用 | Combat Compatibility / Legacy Compatibility，已退出 Person Identity Authority | 不替代 PersonDefinition，不因退出 Authority 就宣布依赖已删除或可删除 |
| 普通人物实例 | `CharacterInstance` | 长期；BattleUI 另有临时视图实例 | PlayerCollection 中的实例持有 Person-owned 长期数据 | 临时同型视图实例不能成为第二套长期真相 |
| 英雄实例 | `HeroInstance` | 长期 | 英雄 Person-owned 数据与营养状态 | 不自动套用普通 Character 的 Profession 迁移 |
| 单场战斗单位 | `BattleUnit` | 单场 Runtime | 单场战斗状态 | 不是长期人物，不直接 Save |
| 稳定人物ID | `PersonId` / `PersonIdentity` | 创建后跨 Save / Load | 具体实例身份；工具只负责生成/校验 | 不用 CharacterId / HeroId / CardId / 名称替代 |
| 模板ID | `CharacterId` / `HeroId` | 配置与实例模板引用 | 标明采用哪个模板 | 同模板可以有多个 Person |
| 卡ID | `CardId` | 依卡类型：定义或 owned 角色卡绑定键 | 角色卡通过 PlayerCollection 显式 Card → Person 绑定 | 不把 CardId 当 PersonId；Legacy Item 模板ID+数量模型不等于人物绑定 |
| 战斗单位ID / 来源ID | `BattleUnit.UnitId` / `SourceId` | 单场 Runtime / 模板来源引用 | UnitId 标识本场单位，SourceId 引用 Character / Hero / Monster 模板 | 数值恰好取自 CardId 也不等于长期人物身份；须显式适配 |
| 长期岗位安排 | `VillageAssignmentSystem`，PersonId → WorkplaceId | Persistent | Assignment records | Assignment ≠ Profession；不是实际执行事实 |
| 临时占用 | Bridge Expedition 登记、Active Project 等既有来源 | Runtime / Derived | 既有 Village Occupancy 组合 | 不新建 Person 长期 Occupancy 字段或第二套字典 |
| Profession | `ActiveProfessionProgress` / `ProfessionProgress` | Person-owned / Persistent | 普通 Character 当前成长容器 | 最终命名、正式内容、数值、Transition / Dormant 未冻结 |
| Formation 基础 | `FormationResolver` / `FormationState` / `FormationRuntimeServices` | 日结 Runtime；状态 Persistent | 已冻结基础流程，消费真实经历事实 | 正式配置/阈值/内容仍 Not Frozen；Assignment 不直接写 Profession |
| 远征连续状态 | `RunState` | 单次 Run Runtime | Person HP、Run Deck、Insight、Pending 事实 | 不兼任 Progression，不直接长期 Save |
| 远征推进状态 | `ExpeditionProgressionState` | 单次会话 Runtime | Node / Elapsed / Supply；写入口为 Resolver | Legacy Map flags、UI、AdventureManager 不另立推进规则 |
| Return 会话记录 | `ExpeditionRecord` + `VillageRuntimeBridge._pendingReturnMode` | 活跃内存会话 Runtime | Phase 是 Begin-or-Resume 入口；原始 `RunEndMode` 随同一 Return 会话保留 | 不进入长期 Save；未完成 Record 不重新 Begin；不构成跨进程事务 |
| 村庄时间 | `VillageTime` | Runtime，时间进度 Persistent | 唯一 Day Tick 时钟 | HUD / Resource Settlement 不另开时钟 |
| 村庄原有聚合状态 | `VillageState` | Runtime / Persistent | 已有 Test 村庄状态 | 不承载 Ingredients / Food 副本或 Person Hunger Dictionary |
| 村庄资源存量 | `VillageResourceState` | Runtime host + Persistent | Ingredients / Food 唯一长期 Authority | 不含 Gold、Carry、Building、Person 营养 |
| 村庄资源日结 | `VillageResourceSettlement` | 单日纯逻辑调用 | 消费真实执行事实，调用资源写入口及 Person host | 不拥有时间、不直接 Save、不操作 UI、不复制 Capacity |
| 食材 | `VillageResourceState.Ingredients` | 长期 | VillageResourceState | 不是 PendingBuildingMaterial 或标准 Expedition Carry |
| 食物 | `VillageResourceState.Food` | 长期 | VillageResourceState | 不等于仍在远征中的 Carry；Gold 另有归属 |
| 远征携带 / 补给 | `ExpeditionSupplyState` / `CurrentCarryUnits` | 会话 Runtime | Progression 消费侧 Supply；Departure / Return 经 Bridge 转移 | 不保存在长期 Village Inventory / Run Save |
| 饥饿状态 | `Hungry`，通过 `IFulfillmentHost` | Person-owned / Persistent | CharacterInstance / HeroInstance | 不是 Village 聚合字典；不自动附加死亡/伤病/战斗减益 |
| 连续未满足天数 | `ConsecutiveUnderfedDays` | Person-owned / Persistent | CharacterInstance / HeroInstance | 正式阈值与惩罚仍 Not Frozen，不等于通用 Mood |
| 金币 | `PlayerCollection.Gold` | 长期 | PlayerCollection；Run PendingGold 是独立暂存量 | 不纳入 VillageResourceState，不恢复旧四资源体系 |
| 暂存建材 | `RunState.PendingBuildingMaterial` | Legacy / Runtime | 无产品生产者，sink 无 Current 长期落点 | 不作为 Food / Ingredients 通道 |

## 2.2 身份适配边界

`BattleUnit` 当前没有 `PersonId` 字段。`BattleUI.GetPersonIdOfUnit` 通过显式角色卡绑定或英雄真实 PersonId 解析归属；`BattleSettlement` 使用外部传入的 `deployedPersonIds`，产品链另注入长期 Person 查询。UnitId / SourceId 只能按其各自技术职责使用，不能按模板猜绑长期 Person。

## 2.3 Post-Bootstrap / V4 增量映射

本表补充生命周期、持久化和实现限制；不是 DTO 字段大全，也不将 Test 配置升级为正式规则。

| 概念 / 实际代码对象 | 所有权与生命周期 | 保存边界 | 状态及禁止混用 |
|---|---|---|---|
| `PersonDefinition` / `PersonDefinitionId` | Person.Runtime 静态配置定义 / 配置链接 | 定义是 SO；长期 Character 保存配置 ID | Current Technical；PersonDefinitionId ≠ PersonId，不是具体人物或卡归属 |
| `PersonId` | PlayerCollection 中具体 Character / Hero 的稳定实例身份 | 跨 Save / Load 保留 | Current；不能由模板、配置 ID、CardId 或姓名替代 |
| `DisplayName` | 人物表现名称；来自配置、存档及兼容显示回退 | CharacterSaveData additive 字段 | Current Technical；不是唯一身份，不按姓名绑定人物 |
| `PersonBootstrapper` | Fresh New Game 创建长期 CharacterInstance | 只保存创建结果；Load 不重跑 | Current；人数由有效初始名册决定，不创建 Battle 临时实例；Legacy 无名册兼容不作正式身份来源 |
| `InitialProfessionConfig` | PersonDefinition 的初始化快照；深拷贝到 Person-owned 进度与 Starter 内容 | 保存结果，不以配置对象替代进度 DTO | Current Technical，内容 Test / Not Frozen；不模拟历史升级，不制造 Formation 事件 |
| `PersonDefinitionCatalog` / `ProfessionDefinitionCatalog` | ExcelImporter 从 CSV 导入 SO，由 DataManager 读取 | 配置资产，不是长期人物 Save | Current Technical；Catalog ≠ 人物集合，不复制 CSV 内容为正式规则 |
| 长期 / 临时 `CharacterInstance` | 前者由 PlayerCollection 持有；后者由 BattleUI 为单场战斗创建并携带 PersonId 链接 | 只保存长期实例；临时不复制 ActiveProfessionProgress | Current；同类或同 PersonId 不等于同一 Authority |
| `LongTermPersonLookup` | BattleSettlement 委托，由 BattleUI 接入 PlayerCollection | Runtime 查询，不保存 | Current 接线；未注入为 Compatibility；已注入null/异常fail closed，未注入仅Compatibility；其它Return债保留 |
| `VillageCapabilityGrant` | Project 完成增量定位长期 Person，写其当前 Growth Pool | 结果进入既有 Person Growth Save，无独立 Capability Save | Current 实现，内容/顺序 Not Frozen；不创建 Global Capability State |
| `ExpeditionReturned` | 普通 Character 的 LifeHistory 经历，由 Return Person Consequence 写入；Hero 不增加同类记录 | 经既有长期人物区块保存；提交标记留在 ExpeditionRecord 会话 | Current 实现；不是 ProfessionExp，也不是新 World Fact 系统 |
| `HasActiveProfessionProgress` | CharacterSaveData 显式存在性哨兵，由 SaveSystem Build / Restore 使用 | 持久化，Restore 先检查再恢复进度对象 | Current；不以 JsonUtility 恢复出的嵌套 class 是否 null 推断有无 Profession |
| Daily Execution Delta / `VillageDailyExecutionFact` | VillageAssignmentSystem 当日实际执行事实，供 Formation 日结消费 | 当日 delta 为 Runtime；累计执行事实另有长期记录 | Current；不是每天重复读取 TotalExecutedDays；VillageTime 唯一日时钟 |
| `RunState.PendingProfessionExp` | PersonId 键控 Run 暂存，成功 sink ack 才清除对应条目 | Runtime，不进入正式 Save | `SettleReturnDetailed` 未全部 ack 时保留，Phase 保持 Active；Retreat / Defeat 只丢弃非 Profession Pending |
| `ReturnSettlementResult` | `SettleReturnDetailed` 的 Settlement 结果 | Runtime，不保存 | `AllProfessionExpAcknowledged` / `SettlementSucceeded` 是产品 Return 越过 Settlement 的条件 |
| `RunEndMode` | Return 出口模式；由 `_pendingReturnMode` 保存同一内存会话的原始值 | Runtime，会话内保留，不持久化 | resume 沿用原模式；不承诺应用退出后的恢复 |

初始化 Profession ≠ M6 Formation；Assignment ≠ Profession。M6 只处理运行期无 Active Profession 人物的首次形成，基础规则 Current，正式算法、名称、内容、数值、Transition / Dormant 继续 Not Frozen。

`CharacterSaveData.PersonDefinitionId` / `DisplayName` 为 additive 兼容字段，SaveVersion 仍为1；旧档缺配置链接沿兼容路径恢复，不重跑 Bootstrap。JsonUtility 缺失/null class 的物化行为不可靠表达无 Profession，必须使用显式哨兵；该实现约束不是永久冻结 Schema。

Lookup 与 Return 的现状详见[技术架构总览](技术架构总览.md)§10.1、§12.1及[问题清单](../问题清单.md)问题90。同一内存会话的失败恢复已实现；跨进程恢复仍未实现，已注入lookup的null/异常已fail closed，未注入Compatibility仍保留。

## CharacterInstance

状态：Current Technical

含义：

# 3. Profession / 身份 / Assignment

## Profession

状态：按范围区分——基础规则与普通 Character 的成长容器为 Current；最终命名、正式内容与数值、Transition / Dormant 为 Not Frozen / Supporting Candidate。

中文讨论中可见：

> 身份 / 职业（不是本文件裁决的最终产品命名）

含义：

> Person 当前形成的长期社会身份及其长期成长。

当前代码和 Save 均已实现：

```text
ActiveProfessionProgress
ProfessionProgressSaveData
```

Person 可有：

```text
0 或 1 个 Active Profession
```

没有 Profession 是合法状态。

Profession 不等于：

- 当前工作；
- Assignment；
- 战斗职业；
- RPG Class；
- 模板身份。

## SaveData

状态：Current Technical

顶层长期 Save 当前保存：

```text

Village
EventWorld

ActivityWorld
AutonomousDecisionWorld
SocialFeedbackWorld
```

不保存：

- Battle Runtime
- RunState
- Expedition Progression Runtime
- Expedition Supply / Carry / ExpeditionRecord（含 RemainingCarryReturned）
- UI
- Camera
- Product Home Presentation
- Temporary Occupancy

当前 Village Save 的 Resources 区块保存 Ingredients / Food，Character / Hero 区块保存各自 Hungry / ConsecutiveUnderfedDays；SaveVersion 保持 1。

顶层 `SocialWorld` 保存独立社会域的 RelationalFacts[] 与 Relationships[]，不属于 Village.Social 或 PersonLifeHistory。当前 Affinity 是 V0.1 Test / Not Frozen channel。Social Restore = Replacement，直接恢复存档状态，不运行 Interpreter；旧档缺区块 → empty，invalid / duplicate data 防御性过滤。所有 Save 入口携带 Social snapshot；Player Restore 成功后才 Restore Social，failed Load 保留旧 Social，successful NewGame reset Social。其它 World Host 的统一事务隔离仍是既有遗留风险，不能由 Social 的保证推导其已修复。

Current Return 编排为 `Settlement → Catch-up → Remaining Carry Return → Return Person Consequence → Clear Occupancy → Unique Final Save`。`FinalizeReturn` 按 Phase Begin-or-Resume；Settlement 未全部 ack 时保持 Active，Final Save 失败时保持 OccupancyCleared 并只重试 Save。同会话恢复不代表 Run Save / Resume、跨进程崩溃恢复、数据库式 rollback / exactly-once 或 stale checkpoint replay。Save 触发职责为 **Existing Implementation / Semantics Pending**：当前产品 UI / 编排链触发最终 Save，资源日结本身不 Save；这种当前调用位置不是已冻结的目标架构。

V4 Return 复用既有 Injury 字段，不恢复 Legacy Death's Door / 全部 Injury 规则。健康与经历的 `HealthConsequenceCommitted` / `ExperienceCommitted` 属 ExpeditionRecord 会话标记；结果归长期 Person，阈值、severity 与正式健康语义仍 Not Frozen。

## 14.2 身份与命名硬边界

```text
Canonical IR          ≠ Save JSON          ≠ Runtime State   ≠ 人工配置源
Config Database       ≠ Save Database      ≠ Player Runtime State
Visual Asset Catalog  ≠ Person Identity Authority  ≠ Gameplay Rule Authority
Stable AssetId        ≠ PersonId           ≠ MonsterId       ≠ EventId
```

- `Stable AssetId` 只标识**资产身份**；不是人物 / 怪物 / 事件身份，不得代替 `PersonId`、`MonsterId` 或 `EventId`。
- `Config Database` 只承载**静态配置**；不得承载 Save 或 Runtime 状态。
- `Visual Asset Catalog` 只负责 `AssetId → UnityEngine.Object`；**不**拥有人物身份，**不**拥有玩法规则。
- `Canonical IR` 是机器镜像；**不是**人工源，**不是** Save，**不是** Runtime 状态。
