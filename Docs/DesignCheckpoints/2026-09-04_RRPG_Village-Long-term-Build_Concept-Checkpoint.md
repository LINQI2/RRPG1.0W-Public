# RRPG Village Long-term Build — Concept Checkpoint

**日期：2026-09-04**  
**状态：Concept Near Closure / 下一关键问题未展开**  
**范围：Village 长期构筑、发展方向、Opportunity、历史路径依赖、Living Tradition / Historical Legacy 前置收口**

---

## 1. 本轮为什么重新讨论 Village Build

原始目标一直不是给 Village 增加一套普通科技树，而是让 RRPG 形成真正的“双构筑”结构：

- **Battle：快速构筑** —— 一次远征内围绕角色、卡牌、组合形成临时 Build；高频、短周期、可重来。
- **Village：长期构筑** —— 数年到数十年中，由人物、经历、Commitment、Project 与历史选择逐渐形成共同体差异；低频、长周期、不可轻易回滚。

本轮核心纠偏：

> **Village Build 不是多个成长条的加法，而必须包含选择、组合、机会成本与失去部分未来的可能。**

---

## 2. 原方案与本轮纠偏

### 原先容易滑向的方案

曾一度把“传承 / 探索 / 守护 / 知识”等理解成可同时积累的隐藏维度，并进一步映射为角色池、卡池、事件池等收益。

问题：

- 如果所有维度都能无脑增长，最终只是“四条成长槽”，不构成 Build；
- 容易退化为手游式养成或隐藏科技树；
- 会诱导为每个方向单独增加铁匠、商人、学院、贸易等大批机制；
- 与 RRPG 的 Person-first、双系统核心不一致。

### 本轮新增纠偏

维度仍可作为后台解释历史的语言，但**不是玩家直接培养的属性**。

真正的长期构筑单位更接近：

> **Opportunity（长期可能性） + Person-Time（具体人的有限人生） + Commitment（把某个未来落实） + History Path Dependence（历史路径依赖）**

---

## 3. 当前确认的 Village Build 核心结构

```text
World / Person / Expedition / Event / History
                ↓
        产生长期 Opportunity
                ↓
多个未来之间发生真实竞争
                ↓
玩家通过有限 Person / Time / Commitment 做选择
                ↓
部分 Possibility 被保留、放大、组合
部分被延后、削弱或永久错过
                ↓
        逐渐形成 Village Build
                ↓
改变未来人物 / 事件 / Project / 战斗可能性
```

### 关键结论

1. **构筑不是路线菜单。**
   - 不做“选择探索路线 / 知识路线”。
   - 玩家处理的是具体人物、具体机会、具体历史节点。

2. **构筑不是属性加法。**
   - 不以“探索 +3 / 传承 +5”作为玩家主要认知与操作语言。

3. **构筑压力优先来自现实机会成本。**
   - 同一个人不能同时把同一段人生投入多个长期未来；
   - 某个 Opportunity 不会永远等待；
   - 已经发生的历史不能重新拥有另一种人生版本。

4. **大部分方向不需要硬锁。**
   - RRPG 更偏历史路径依赖，而不是预制路线树。

---

## 4. 村庄构筑真正稀缺的“资源”

### 4.1 Person-Time —— 当前最核心

不是木材、金币或科技点，而是：

> **具体人物拥有的有限人生时间。**

例如一名老角色晚年可能：

- 继续参加最后一次高价值远征；
- 留村培养年轻人；
- 主持一个长期 Project。

三个未来都合理，但这个人的时间只有一份。

本轮形成的重要原则：

> **不可逆的主要不是路线，而是人生。**

### 4.2 Commitment —— 将 Person-Time 变成真实选择

现有 V2 的 Primary Assignment / Temporary Commitment / Project Occupancy 不只是 Runtime 骨架，也天然可以承担 Village Build 的机会成本：

> 把某个具体人投入某个长期 Project，就意味着他在同一段时间不能完整投入其它未来。

因此暂不需要额外建立抽象的 `Village Attention` 资源条。

### 4.3 Opportunity —— 慢速构筑的“抽牌”

Opportunity 来自：

- 具体人物；
- 远征发现；
- 外来者；
- 长期 Pattern；
- 历史节点；
- 环境变化；
- Event / Social Response。

建议区分：

- **Stable Possibility**：基础、长期存在，可稍后处理；
- **Historical Opportunity**：与具体人物 / 时机 / 历史绑定，可能真正错过。

后者承担更高的构筑重量，但必须克制，避免 FOMO。

### 4.4 普通资源与空间

- 木材 / 食物 / 金钱：主要控制节奏与可行性，不应成为共同体身份的核心来源；
- Grid / Space：未来可以产生空间机会成本，但当前不反推整个 Village Build，避免退化为城市建设模拟。

---

## 5. 互斥与不可逆：当前四层模型

### A. 自然不可逆 —— 应大量存在

- 年龄增长；
- 死亡；
- 已经度过的人生阶段；
- 已发生的远征 / 选择 / 成长。

来源是时间与人生，而非 UI 锁线。

### B. Opportunity 不可逆 —— 适量存在

- 特殊人物只停留有限时间；
- 老人收徒窗口；
- 某个历史阶段的独有机会；
- 只在某次危机中存在的选择。

适合作为多周目差异来源，但不应用于基础建筑与基础生存能力。

### C. 历史路径依赖 —— 主要软互斥

过去形成的人物、Place、传统、关系和行为模式，会让同方向未来更容易继续，也让转向需要新的时间与历史投入。

特点：

- 不永久锁死；
- 有文化惯性；
- 可以转向，但不能无成本瞬间重置。

### D. 制度性硬互斥 —— 极少使用

只在两个未来**逻辑上确实不能同时成立**时使用，例如真正冲突的制度或共同体规则。

不将整套 Village Build 做成 Frostpunk / Civilization 式显式分叉树。

---

## 6. “树”的重新定义

早期设想：

> 多次互斥选择形成一棵发展树，以支持多周目不同路线。

本轮并未否定“树”的目标，而是改变了树的位置：

- **不把整棵树提前展示给玩家；**
- 玩家通过具体 Opportunity 和 Commitment 一步步经历；
- 事后回看，才看到这个村庄形成了一棵独特的历史树。

因此：

> **玩家不是走一棵预制树，而是在生成自己的历史树。**

---

## 7. 维度 / Identity 的当前定位

### 维度不是成长条

“传承 / 探索 / 守护 / 知识 / 信仰……”等可以继续作为后台解释世界的开放维度空间，但：

- 不要求玩家直接操作；
- 不需要显示数值；
- 不等于路线；
- 不要求每个维度建立一整套独立经营机制。

### DLC 扩展逻辑仍成立

未来 DLC 可以新增新的解释维度（例如信仰、自然、秩序等），并与既有历史事实 / Opportunity / Tradition 重新组合，形成新的共同体结果。

重点不是“新增一条科技树”，而是：

> **新增历史被解释和沉淀的方式。**

---

## 8. 建筑 / 职业 / 制度的位置

本轮确认它们不是 Village Build 的唯一核心单位。

### 建筑

- 基础建筑可以只是运营工具；
- 关键建筑可以成为某段历史的物质载体；
- 不要求每个 Identity 都发展出完整产业系统。

### Profession / 人物

- 具体人物和其人生经历是 Village Build 的核心输入；
- Profession 可以影响 Opportunity / Tradition，但不应成为“路线钥匙”；
- 人的有限时间比抽象职业槽更适合作为构筑压力。

### 制度 / 习俗

- 可作为后期高重量构筑结果；
- 适合承载少量真正逻辑冲突的硬互斥；
- 当前不提前扩成政治模拟系统。

---

## 9. 双系统关系重新确认

RRPG 是双核心，不是“村庄模拟 + 战斗附属”。

```text
Battle / Expedition
→ 产生人物经历、发现、伤痕、关系、外部信息
→ Village 接住并决定哪些东西被保留 / 放大 / 传承
→ 改变未来人物、Project、Event、Possibility、战斗内容
→ 新的 Expedition
```

本轮形成的一句核心表达：

> **战斗创造经历，村庄决定哪些经历被留下。**

以及：

> **历史可以全部留下，但活着的共同体不能同时活成所有样子。**

---

## 10. 已降级 / 暂不采用的方案

- 固定“传统槽位上限”；
- 四个 / 五个可同时升级的 Identity 数值条；
- 大量显式 A/B 永久锁线；
- 所有 Village Opportunity 固定每月 / 每次远征后三选一；
- 将 Village Build 主要建立在木材、金币、科技点等普通资源上；
- 为每个发展方向单独建设完整铁匠 / 商业 / 学术 / 政治大系统；
- 将所有传统永久收藏，导致百年后所有方向叠满。

---

## 11. 新增关键概念：Living Tradition vs Historical Legacy

为解决长期游戏最终“什么都有”的趋同问题，本轮提出区分：

### Living Tradition

当前仍有人在：

- 实践；
- 传授；
- 回应；
- 通过具体人物 / Place / Opportunity 持续再生产。

它继续显著影响当前与未来的 Possibility Pool。

### Historical Legacy

过去曾经重要，但当前已不再被持续实践。

它仍可留在：

- 村庄日志；
- 历史记录；
- 建筑；
- 家族 / 师承；
- 人物经历；
- 场景痕迹。

但不再等同于一个当前强势的“活传统”。

这一分离用于支持：

- 传统形成；
- 传统衰退；
- 村庄转向；
- 长历史不丢失；
- 当前共同体身份不无限叠加。

---

## 12. 仍未解决的问题

### 当前第一优先级

> **Living Tradition 到底什么时候算“活着”？什么时候只是 Historical Legacy？**

下一轮需要讨论：

- 一个传统如何形成；
- 什么叫持续实践；
- 是否必须有人传授 / 使用 / 回应；
- 人物全部死亡后，建筑或日志能否单独维持传统；
- 一个传统如何衰退；
- Historical Legacy 是否可以重新激活成 Living Tradition；
- 重新激活需要什么世界事实，而不是抽象数值。

### 后续问题

- 哪些 Opportunity 值得真正永久错过；
- 哪些制度选择值得硬互斥；
- 维度组合何时需要设计高价值明确结果，何时只让内容自然涌现；
- Village Build 对角色池 / 卡池 / Event / World 的具体影响边界；
- 多周目如何利用历史差异，而不变成强制重开才能体验内容。

---

## 13. 下一步

**建议明日从 Living Tradition / Historical Legacy 开始。**

理由：

1. 今天已完成 Village Build 的“为什么不能全都要”的核心逻辑；
2. Opportunity / Person-Time / Commitment / Path Dependence 已形成清晰骨架；
3. Living Tradition 正好是“Build 如何形成、维持、衰退、转向”的下一层，不需要回头重聊 Identity 类型；
4. 如果今天继续展开，会进入一个新的完整子问题，不利于在下班节点收尾。

---

## 14. 当前一句话总结

> **RRPG 的 Village Build 不是科技树，也不是成长条，而是：世界不断产生长期 Opportunity，玩家用有限的具体人生和 Commitment 保留其中一部分未来；这些选择彼此组合并形成历史路径依赖，最终让每个共同体拥有不同的 Living Tradition，同时把过去沉淀为 Historical Legacy。**
