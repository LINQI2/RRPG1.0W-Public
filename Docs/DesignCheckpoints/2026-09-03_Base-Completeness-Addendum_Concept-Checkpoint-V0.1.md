1. Failure / Loss
2. Population Renewal

# 1. Failure / Loss

## 1.1 为什么必须存在失败代价

失败代价的目标不是单纯惩罚玩家，而是：

- 让远征风险真正有重量；
- 让准备、判断、撤退、止损有意义；
- 防止无成本反复撞墙；
- 抑制无限滚雪球；
- 让 Battle 的结果真正回到 Person / Village / History。

总原则：

> **失败不是为了让玩家倒退，而是为了让一次没有达到目标的远征留下有意义的人生与共同体后果。**

---

## 1.2 已确认原则

### Consequential

失败必须改变后续决策，否则风险没有意义。

### Recoverable

失败优先作为 setback，而不是默认造成不可逆崩坏。

### Retreat = Stop-Loss

Retreat 是主动止损。

Defeat 是没有成功止损后的更差结果。

### Strategy-Preserving

失败成本不能高到让玩家只敢使用最稳阵容、最稳 Build，从而压缩卡牌构筑和六人组合实验空间。

### History-Relevant

失败必须有资格回流到：

- Person
- Village
- Experience / Life History
- Social Response
- Return / Reorientation

而不能只停留在 Battle Settlement。

### Permanent Loss Is Exceptional

普通 Defeat 默认不依赖：

- 永久死亡；
- 长期成长抹除；
- 建筑倒级；
- 重大永久资产销毁。

如果未来存在长期或永久损失，应属于：

> **明确、可预期、特殊内容级风险**

而不是普通失败默认结果。

---

## 1.3 强候选但未冻结

以下是当前最适合 RRPG 的失败成本类型，但仍需结合 V4 实际 Expedition、时间价值、恢复系统验证：

### Opportunity Loss

失去本次主要目标收益 / 战利品 / 机会。

### Time Loss

远征耗时已经支付，Village 世界继续运行。

### Recoverable Person State

人物归来后可能带有可恢复的伤病、疲惫或其它状态。

### Generative Consequence

失败可能生成：

- 新 Experience；
- Recovery；
- Character / Village Event；
- Social Response；
- 新的后续问题。

### Limited Resource Loss

资源损失可以存在，但更适合作为辅助成本，不宜默认成为主轴。

---

## 1.4 明确未冻结

- Retreat / Defeat 具体损失比例；
- 是否损失已有 Village 资源；
- 是否保留部分远征收益；
- 伤病持续时间；
- 是否存在恢复设施；
- 是否存在长期后遗症；
- 哪些特殊内容允许永久损失；
- Failure Event 具体内容；
- Run HP → Village Health 映射；
- Retreat 是否能保留部分目标；
- Defeat 是否强制结束 Expedition；
- 撤退节点与撤退条件。

---

## 1.5 Failure Anti-Gate

当前明确不倾向：

- 为了“真实”把所有惩罚叠加；
- 默认同时执行“没奖励 + 浪费时间 + 人物受伤 + 扣资源 + 掉成长”；
- 一次失败显著削弱后续很多次尝试，形成 death spiral；
- 让最喜欢、最有长期价值的人物变成“最好永远别带出门”的资产；
- 让 Retreat 成为没有实际价值的假按钮；
- 让 Defeat 只是更大数值罚款；
- 让失败只存在于 Battle UI，而不进入人物与共同体历史。

# 2. Population Renewal

## 2.1 为什么属于 Base Completeness

如果 Person 会：

> 年龄增长 → 衰老 → 自然寿终

而没有新人：

> Population 将长期单调下降。

因此跨世代共同体在数学上和体验上都无法持续。

所以：

> **Population Renewal 是 Base Completeness 的硬需求。**

但：

> **Population Renewal ≠ Reproduction System。**

---

## 2.2 已确认原则

### Specific Person

新人口必须最终成为具体 Person，而不是：

> `Population +1`

否则会破坏“Person 是一等对象”的核心。

### Renewal ≠ Full Family Simulation

人口续接不自动等于：

- 恋爱；
- 婚姻；
- 怀孕；
- 婴儿照料；
- 完整家庭模拟。

### Multiple Sources

内部新一代与外部加入应能并存。

两者的设计意义不同：

- **内部新一代**：承担共同体延续与代际连续性；
- **外部加入**：承担人口恢复弹性与 Outside → Village 的连接。

### Shape Conditions, Don’t Manufacture People

玩家主要塑造人口续接条件，而不是直接点击：

> “生产一个 Person”。

这和长期身份 Formation 的哲学一致：

> 塑造环境、机会和共同体条件，而不是直接生产结果。

### Capacity + Responsibility

人口增长不能是纯奖励。

更多 Person 意味着：

- 更大的 Assignment / Project / Expedition 能力；
- 更多未来组合；
- 同时也意味着更高维持负担和更复杂共同体。

### Resilience

Population Renewal 还承担系统恢复能力：

> 损失要有重量，但共同体不能因为几次损失永久陷入无法恢复的下降螺旋。

### Protect Person Recognizability

人口规模不能无限扩张到破坏：

> 玩家能够认识、记住具体 Person

这一产品核心。

---

## 2.3 强候选：儿童阶段成为轻量真实 Person

当前强候选：

> **下一代在儿童阶段开始成为轻量、真实、可观察的 Person，而不是接近成年时突然生成。**

原因：

- 玩家可以见证成长；
- Life History 更连续；
- “这个共同体养出了怎样的人”更可信；
- 未来长期身份 Formation 有真实人生前史。

但这条**仍不冻结为正式 Base 实现要求**。

当前只确认：

> 下一代必须有真实存在感。

尚未确认：

> 必须从哪一年龄阶段正式进入 Person Runtime。

---

## 2.4 其它强候选

- 内生续接 + 外来者多通道；
- 儿童首先承担世代连续性，而不是生产优化；
- 外来者可先通过 Event 等轻量方式进入，不要求立即建立独立 Migration System；
- 共同体环境、教育机会、重要经历未来可能参与下一代成长塑形；
- 人口增长可以自然承载“发展 ↔ 共同责任”的主题张力；
- 生命周期最终需要适配实际玩家游玩长度，使玩家能够在合理时间内看到世代变化。

---

## 2.5 明确未冻结

- 出生率；
- 恋爱 / 婚姻；
- 怀孕；
- 婴儿期；
- 从几岁开始成为正式 Person；
- 成年年龄；
- 生命周期倍率；
- 人口上限；
- 移民频率；
- 外来者具体来源；
- 儿童 Assignment；
- 教育系统；
- 家庭结构；
- 住房；
- 父母子女关系是否系统化；
- 下一代与 Profession / Identity Formation 的具体算法；
- 人口增长的正式 Maintenance Cost。

---

## 2.6 Population Renewal Anti-Gate

当前不倾向：

- 因为需要下一代，就自动复制完整育儿模拟；
- 把儿童做成“低效率 Worker”；
- 把人口增长做成纯数值正收益；
- 新人口无限、即时、免费补充，导致 Person 损失失去重量；
- 人口完全不可补，导致 Failure 形成死亡螺旋；
- 为了“真实”提前建立完整婚恋、家庭、血缘模拟；
- 人口规模大到玩家无法记住具体人物；
- 后期人口增长只带来同比增加的重复点击和微操作。

# 3. Campaign End-State

## 3.1 核心方向

RRPG 不需要：

> 一个统一、强制、规则化、僵化剧情式的固定胜利终局。

不要求：

```text
第 X 年
→ Final Boss
→ 唯一 Ending
→ Credits
→ 存档结束
```

更适合的总体结构是：

> **Open-ended Campaign + Emergent Collapse + Optional Culmination**

---

## 3.2 已确认原则

### No Mandatory Unified Victory Ending

Village Campaign 不要求统一强制胜利终点。

### Open-Ended Community

Battle、Expedition、Person Life、Generation 都可以有清晰终点。

但：

> **共同体本身可以长期开放持续。**

### Emergent Collapse

Collapse 可以由玩家自己的经营结果和真实系统状态自然产生。

例如：

- 共同体彻底失去延续条件；
- 全体成员死亡 / 永久离开；
- 长期生存结构彻底失败。

这属于：

> **系统事实导致的历史终止**

而不是设计师强塞的坏结局剧情。

### Culmination ≠ Forced Ending

可以存在由长期历史造成的：

> Culmination Event / 历史节点

为需要目标感的玩家提供阶段收束与成就感。

但原则上：

> **正向收束不等于强制结束 Campaign。**

### Community History Creates End-State

终局 / 收束应更接近：

> **这个共同体最终活成了什么样**

而不是：

> 设计师预先规定唯一正确答案。

### Different Time Scales

需要区分：

- Battle 有终点；
- Expedition 有终点；
- Person Life 有终点；
- Generation 有终点；
- Village Campaign 可以开放持续。

总锚点：

> **具体生命和行动都有终点，但共同体本身不需要一个设计师强制规定的统一终点。**

---

## 3.3 强候选但未冻结

### Culmination Events

可能由：

- 长期共同体历史；
- Theme Branch；
- 重大 Project；
- 探索成果；
- 某种长期社会状态

触发阶段性收束。

### Post-Culmination Continuation

可能出现：

- 历史总结；
- 阶段评价；
- Credits 式仪式性收束；

但允许继续游戏。

### Theme / DLC Expansion

未来 Theme Branch / DLC 可以新增：

> 新的问题空间 + 新的历史收束可能

而不是续写唯一线性终局。

---

## 3.4 明确未冻结

- Collapse 后 Save 是否永久结束；
- 全村灭亡后是否允许后来者重新占据废墟；
- Culmination Event 数量；
- Culmination 具体内容；
- 是否出现 Credits；
- 是否允许玩家主动退休共同体；
- 是否存在世界级终极目标；
- DLC 是否各自拥有独立收束；
- 历史总结 UI；
- 成就 / 评分 / 年表结构。

---

## 3.5 Campaign End-State Anti-Gate

当前不倾向：

- 为了“目标感”硬塞唯一主线终局；
- 因为没有强制终局，就放弃中长期目标；
- 把 Culmination Event 做成僵化 Ending A/B/C 树；
- 要求所有玩家必须触发某个结局才算“玩完”；
- 让长期共同体只服务于最终 Boss；
- 把开放沙盒误解成“没有方向、没有阶段成就”。

# 4. 三个专题之间的关系

这三个 Base Completeness 问题并不是彼此独立。

```text
Failure / Loss
  ↓
人物与共同体承担后果
  ↓
Population Renewal 提供恢复与代际延续
  ↓
共同体可以长期存在
  ↓
Campaign 不必依赖固定胜利终局
```

同时：

```text
长期开放 Campaign
  ↓
人物会老去 / 寿终
  ↓
必须有 Population Renewal
  ↓
人物损失有重量但不能绝对不可恢复
  ↓
Failure / Loss 需要避免死亡螺旋
```

因此它们共同服务于：

> **一个能长期持续、会真正变化、又不会因为一次失败彻底失去未来的共同体。**

# 5. 当前分层状态

## 已确认

- Failure 必须有后果，但目标是提升决策质量而非惩罚；
- Retreat = 主动止损；
- 普通失败优先 setback，不默认永久毁坏长期成长；
- Population Renewal 是 Base Completeness 硬需求；
- Population Renewal 不等于完整生育 / 家庭模拟；
- 新人口必须最终成为具体 Person；
- 内部下一代与外部加入应能并存；
- 人口增长必须同时带来可能性和责任；
- Campaign 不需要统一强制胜利终点；
- Collapse 可由真实经营结果自然发生；
- 可以存在不强制结束的阶段性 Culmination；
- 不同时间尺度有不同终点，共同体可以开放持续。

## 强候选

- Failure：Opportunity Loss / Time Loss / Recoverable Person State / Generative Consequence；
- Population：儿童阶段成为轻量真实 Person；
- Population：内部新一代 + 外来者多通道；
- Campaign：多种 Culmination Event；
- Campaign：收束后继续经营。

## 明确未冻结

- 所有正式失败数值；
- Person 长期健康映射；
- 儿童与家庭具体模型；
- 生命周期参数；
- 人口增长公式；
- 外来者来源算法；
- Culmination 具体内容；
- Collapse 后 Save 行为；
- Credits / 历史总结 / 主动退休等正式产品结构。
