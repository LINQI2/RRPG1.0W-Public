# 4. Y1–Y5 Final Decisions（制作人裁决）

**落地**：Village-GameSpec-V0.1.md §3.4、§4.15、§5.8、§11.4 四处已加 Y1 注记（2026-09-07）。

## 4.2 Y2｜Expedition Supply 抽象 vs Food 产品映射

**问题**：`GameDesign/07 冒险系统.md` §7.6 保留“Expedition Supply 保持抽象 / 不写死 Food / Food 映射未冻结”类表述。

**裁决**：

**落地**：GameDesign/07 §7.6 已按此更新（2026-09-07）。

## 4.3 Y3｜Remaining Carry Return hook（V4F Return 插入位置）

**裁决（固定顺序）**：

```text
Settlement
↓
Keep Expedition Occupancy
↓
Catch-up all elapsed days
↓
Return Remaining Carry
↓
Clear Expedition Occupancy
↓
Unique Final Save
↓
Home
```

规则：

- Remaining Carry 在 Catch-up 完成后才能返还；
- 必须早于 Clear Expedition Occupancy；
- 必须早于唯一 Final Save；
- Return Carry 不得参与返回前 Catch-up；
- 不允许新增第二次 Final Save；
- 必须保持 exactly-once；
- Final Development Spec 必须定义 session-level Carry Return exactly-once guard / equivalent contract；
- FP-V0.1 不要求为该 guard 新增 Run Save / Resume 持久化。

> 说明：V4F 既有冻结顺序（Settlement 不 Save → 保持 Occupancy → Catch-up → Clear → 唯一最终 Save → Town）保持不变；Carry Return 作为不新增 Phase / 不新增 Save 的语义步骤插入 Catch-up 完成之后、Clear 之前，代码级调用位置与 guard 由 WP-3 Final Development Spec 锁定。

## 4.4 Y4｜Village Day Tick（Day-Start Snapshot + Day-End Release）

**裁决（固定每日顺序）**：

```text
1. Capture Day-Start Snapshot
2. Resolve active Assignment / Staffing
3. Building Production
4. Building Processing
5. Advance Project daily progress
6. Village Meal Resolution
   Food → Emergency Ingredients → Person Fulfillment → Hunger
7. Day-End World Facts / History / Pattern / Formation
8. Apply Day-End releases / transitions
```

核心语义：

- 当天所有资源生产、加工、Food Demand、Staffing 使用 Day-Start Snapshot；
- 当日 Project 完成者仍视为整天被 Project Occupied；
- Project 完成释放后，从下一正常 Day Tick 才重新贡献 Primary Assignment；
- Return Person 在所有 Catch-up Day Tick 中保持 Away；
- Catch-up 完成后 Return / Clear；
- Return Person 从下一正常 Village Day Tick 开始重新产生 Village Food Demand / Staffing；
- FP-V0.1 不做半天工时。

## 4.5 Y5｜Expedition elapsed time Authority（整数 Village Days）

**裁决**：

- FP-V0.1 Expedition elapsed time 统一使用**整数 Village Days**；
- Node / Progression 的 elapsed-time cost：`NodeElapsedDays = integer >= 0`；
- 成功正式结算后 exactly-once 累加：`ExpeditionElapsedDays += NodeElapsedDays`；
- 同一 Authority 同时驱动：
  - Supply：`BaseSupplyConsumption = PartySize × NodeElapsedDays × PerPersonDailyConsumptionRate`
  - V4F Catch-up：`EffectiveElapsedDays = ExpeditionElapsedDays`
- 并要求最终：`DaysSimulated == EffectiveElapsedDays`；
- FP-V0.1 不支持小数天 / 小时级 elapsed time；
- 更细时间模型 Deferred，直到未来正式 Work Hours / Daily Schedule 有真实消费者。
